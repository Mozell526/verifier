# LLM 主动健康探测与降级设计

## 目标

公共 LLM 调用设施在健康状态超过三分钟未更新时，先并行执行真实、极短的模型生成探测，再把用户请求发送给优先级最高的健康端点。探测不复用业务 case，不修改业务上下文，对 Judge、Draft、Attribute 等调用方透明。

## 决策

- 健康有效期和失败冷却期均为 180 秒。
- 健康探测调用端点自身配置的模型，通过 Chat Completions 发送带随机 nonce 的短输入，最多生成 4 token。
- 全部待探测端点并行执行，整轮最多等待 10 秒。
- 同一进程同一时间只执行一轮探测；并发业务请求等待并复用该轮结果。
- 真实业务调用成功会刷新端点健康时间；真实业务失败会立即切换到尚未尝试的下一端点。
- 单个业务请求最多在每个配置端点执行一次，不在同一坏端点上重复消耗等待时间。
- 探测失败的端点进入冷却；如果全部端点均不可用，仍选择最早结束冷却的端点执行一次真实请求，避免仅凭探测永久阻断业务。

## 非目标

- 不运行固定业务评测 case。
- 不使用 `/models` 作为健康结论。
- 不在项目层分别实现 Judge、Draft 或 Attribute 专用降级。
- 不增加新的用户配置项；三分钟和十秒是本次已确认的公共策略。

## 验证

- 并行探测只执行一次并被并发请求复用。
- 三分钟内不重复探测，过期后重新探测。
- 探测成功和真实业务成功均刷新健康状态。
- 三端点连续失败时按优先级各尝试一次，第三端点不会被遗漏。
- 探测超时不会无限阻塞业务请求。
