# Report — 认得的只有这一块，出口放在哪

用户本轮钉死：认得的只有「用户要的这件事，产品把它立成自己会做的事了没有」，不是「第二问」。问的是这块东西放在哪：只补没办成，还是新增一个 judge 结果标签，还是 fulfilled 3 扩 4，还是放进 NE，还是别的方式。给方案。不实现。

官方对手 r2 spawn-id `8481552ab6d86f98`。闸：exit 0，隔离有效，范围有效。r1 先被记成 isolation-failed，不当官方。

## 先答「凭什么这样放」

合理，不是因为有人把它叫做第二问。合理，是因为这块东西自己的单位、对象、和已经在的那一格对不上。

1. **单位不是一套。** 这块东西看「这件事 × 产品事实」，不看这一次给没给到。fulfilled 看「这一次请求 × 这一次交付」。`fulfilled.md` §1 只评办成了没有；`product-function.md` §1 写明一张表 / 一个标签 / 一句结论不能同时答两件。
2. **对象仍是那一件。** 用户自己禁止另立类型表，也禁止把对象切粗或切细。所以若要看见，只能跟同一条期望走，不能先收成案子芯片，也不能先收成种类表。
3. **只补没办成会弄丢一格。** `authority.md` §8.3：职责内能力缺失不强制改状态，这次给到了仍可办成了。040 第 4 条：办成了，不能自动排除没立住。只挂在没办成后面，「办成了 × 没立住」消失。
4. **扩成四个词，嘴还是 fulfilled 的嘴。** 第四个词写进 `status` / `fulfillment_status`，答的还是办成了没有。047 已经锁过：同一张嘴兼答，几乎一定对齐刚才的办成了没有。这正是「Judge 都判成办成了，还会不会改口」会塌掉的原因。
5. **放进说不清，会换错「说不清」。** fulfilled 的说不清是「这一次办没办成，现在说不准」。这块东西的说不清是「还不能谈立住」。§8.3 里职责内能力缺失偏偏不是 NE。

所以不是塞回三个词，也不是只给没办成作注。是这块东西自己占一格。

挂在同一行，是因为对象仍是那一件，不是因为有人把它叫做兄妹问。

人看见时多一格字，安放上可以说是一个结果标签。那是安放，不是命名，也不是让 Judge 再写一个 status。

## 方案

```text
用户认得的这一块，出口单独开一格。
这是点名里的「别的方式」。
它不是 fulfilled 的词。
若出现在人正在看的评估结果上，挂在同一条期望、「办成了没有」旁边。
人看见的那一格字，安放上可以说是一个结果标签；
这不是这块东西的名字，也不是选了「新增一个 judge 结果的标签」。
谁写下的：读已经裁完的前缀，不是同一张嘴再判。
```

| 点名口 | 能不能当整句方案 |
|---|---|
| 只是没办成的补充 | 不能。「办成了 × 没立住」会消失 |
| 新增一个判定再写的结果标签 | 不能。同一张嘴会对齐刚才的办成了没有 |
| fulfilled 从 3 态扩到 4 态 | 不能。第四个词仍是第一格的嘴 |
| 放到说不清里面 | 不能。说不清答的是这一次办没办成现在说不准 |
| 别的方式：自己的派生看见格 | 这就是方案 |

人现在只能看见 fulfilled，是因为这一格还没开。不是因为它属于这三个词里的某一个，也不是因为它只属于没办成。
