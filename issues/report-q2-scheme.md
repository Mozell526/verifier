# Report — 开第二问自己的格子，方案是什么

用户问的是：开第二问自己的格子，本质上不就是新增一个 judge 结果的标签吗？按 fulfilled 的定位，它是不是只补没办成；该新增一个 judge 结果标签，还是 3 扩 4，还是放到 NE，还是别的方式。给方案。本轮不改判定，不改界面，不加字段。

官方对手 spawn-id `344d097baef18f39`。闸：exit 0，隔离有效；`scope_valid=false` 全是 host 写的 context_store 旁路落盘，按惯例豁免。

两问结构不改。第一问已经有出口。第二问仍是读已经裁完的产品事实。

## 先答这一句

是。若打开第二问自己的格子，看结果的人会多看见一格字。这一格字出现在 Judge 评估结果上，就是一个结果标签。

方案就是新增这样一个兄妹标签。不是再交一份「四个口都不能当宿主」。

三层必须分开，不得焊回一句：

```text
人看见的：是。结果上多一格字。
谁写下的：不是同一张嘴再判一次。
进哪张嘴：不是改写办成了 / 没办成 / 说不清。
```

承认叫法，不等于批准「判定再写一个词」，也不等于本轮打开。

## 方案

```text
在同一条期望的 judge 结果上看见层，新增一个兄妹结果标签。
挂在 fulfillment_panel 矩阵同一行、Status 旁边。
这就是「开第二问自己的格子」。
在人看见的那一层，这就是新增一个 judge 结果的标签。
```

写/枚举层选的是「别的方式」：派生兄妹格。
看见层收下的是「新增标签」那半句。

| 点名口 | 能不能当整句方案 |
|---|---|
| 只是没办成的补充 | 不能。办成了 × 没立住 这格会消失 |
| 新增一个判定再写的结果标签 | 不能。同一张嘴会对齐刚才的办成了没有 |
| fulfilled 从 3 态扩到 4 态 | 不能。第四个词仍是第一问的嘴 |
| 放到说不清里面 | 不能。说不清答的是这一次办没办成现在说不准 |
| 别的方式：看见层兄妹标签 | 这就是方案 |

人现在只能看见第一问，是因为第二问还没有自己的格子。不是因为它属于这三个词里的某一个，也不是因为它只属于没办成。
