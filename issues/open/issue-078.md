# Issue #078: 承认「方案是新标签」，不会让 NF 补充 / 3 扩 4 / 放进 NE 复活

**Class**: architecture
**Severity**: high
**Status**: verifier-raised
**Evidence**: code-analysis
**Layer**: 四个点名口 / 方案不是那三个口
**Cases**: 只作落点碰撞，不重判。

## Verifier Discovery

用户并列四个口，要选一个当方案：

| 点名口 | 上一轮 | 本轮还能否当整句方案 |
|---|---|---|
| A. 只是 not_fulfilled 的补充 | 062 不能 | 仍不能 |
| B. 新增一个 judge 结果的标签 | 065 把整句焊成「判定再写」后杀掉 | 整句不能；看见层那截就是 077 的方案 |
| C. fulfilled 从 3 态扩到 4 态 | 064 不能 | 仍不能 |
| D. 放到 NE / 说不清 | 063 不能 | 仍不能 |

077 承认看见层是新标签，有人会听成：那不就该并进现在那一枚芯片，或者只给没办成加注脚吗？本 issue 钉：承认标签，不会让 A / C / D 复活。

### 为什么不是只补没办成

`spec/alg/fulfilled.md` §2.2：没办成不区分原因。功能未实现也是没办成。
第一问不看产品立没立住。第二问不看这一次给没给到。

两问是 3×3，不是 NF 的子枚举。办成了 × 没立住 这格必须还能写。若第二问只在 not_fulfilled 后出现，这格消失，过严 / 互有对错也对不上 `product-function.md` §6 的对照表。

现行主表把 `not_fulfilled` 和 `not_evaluable` 收进同一侧统计（`summary.html` `stat-not-fulfilled`），更不能再把第二问塞进这侧当附注。

### 为什么不是 3 扩 4

`fulfilled.md` 开篇：不新增第四态。
`info-volume.md`：值域统一三态，不引入 partial。
第四个词仍走 `JudgeFulfillmentAssessmentOutput.status` 和主表 `fulfillment_status` 芯片。那是第一问的嘴。给它加颜色，买到的只是最熟的那一格，第二问没有自己的格子。

### 为什么不是放进 NE

`fulfilled.md` §2.3：说不清答的是这一次办没办成现在说不准。职责外 / 完全无关 / 依据不充分 / 输入坏，都是第一问材料不够。
第二问的「说不清」是产品事实看不清立没立住。两件都叫说不清，不是同一个出口。
把第二问放进 NE，职责外会被听成「产品没立住」，功能未实现也会被从没办成降级出去，和 §2.2 打架。

### 半句 B 留下什么

B 整句 = 「新增一个由判定写出的结果标签」→ 仍死（065 / 047：同一张嘴会对齐刚才的办成了没有）。
B 看见层那截 = 「结果上多一个兄妹标签」→ 就是 077 的方案。

不得把 077 听成「选了整句 B」。也不得因为 077 叫它标签，就把方案改回 A / C / D。

### 可证伪

若承认 077 之后，必须把第二问并进 `fulfillment_status` 三个词、只在 NF 行出现、或改写 NE 含义，本 issue 失败。
若本 issue 再把 077 改回「四个口都没有方案」，本 issue 失败。

## Proposed Change

Consensus 只锁：方案是兄妹标签；A / C / D 整句仍死；B 整句仍死，留下的是看见层那截。

### Reasoning
三记攻击分开答。不把 077 的段落再贴一遍。

1. 人现在只看一枚芯片。剩余既然叫「judge 结果标签」，老实位置不就是他们已经在看的那一格吗？
不是。那一格今天只答第一问。把它兼答第二问，买到的不是「老实」，是 064 杀掉的第四种颜色，或 062 杀掉的 NF 附注。`product-function.md` §1 L38：「任何一张表、一个标签、一句结论，都不能同时回答这两件。」人现在只看一枚芯片，只证明看见层没开，不证明第二问属于这三个词。061 / 066-q2 已经写过。把「是标签」兑换成「所以进现有芯片」，是把看见层焊回进哪张嘴。章程禁止这种焊。

2. 兄妹格要点进矩阵才看见，算不算没答「用户怎么看到」？
第一眼看不见，是真的。`renderFulfillmentMatrix` 住在 `renderJudgeCard` 的手风琴里。但这不能倒推「所以必须写在主表芯片上」。060 已经锁：规范格子不是案件表「状态」的第四种颜色；主表最多以后做这些行的派生投影，不能重新变成一枚「状态」芯片。第一眼看不看得见，是打开与否 / 主表要不要做派生投影，交 061 / 章程 §4。为了第一眼看得见把第二问塞回芯片，是用看见问题复活 C。078 拒的就是这一跳，不是拒回答「人看见的是标签」。

3. 承认是标签之后再拒 A/C/D，是不是字词游戏？
不是。A / C / D 死在问的内容，不该死在「能不能把一格叫标签」。
- A：第二问若只在 `not_fulfilled` 后出现，「办成了 × 没立住」这格消失。`authority.md` §8.3 正格写明：职责内能力缺失、实际达成 → 第一问仍可 `fulfilled`。这一格必须还能写第二问。`product-function.md` §6 的对照表也要求它在。只补 NF，过严 / 互有对错都对不上。
- C：第四个词仍走 `JudgeFulfillmentAssessmentOutput.status` 和主表 `fulfillment_status`。那是第一问的嘴。只买到「没办成 × 没立住」最熟的那一格。
- D：两种说不清不是同一个出口。第一问 NE 是这一次办没办成说不准（职责外 / 完全无关 / 依据不充分 / 输入坏）。第二问说不清是产品事实看不清立没立住。塞进 NE，职责外会被听成「产品没立住」，功能未实现也会被从没办成降级出去，和 `fulfilled.md` §2.2、§8.3 打架。现行统计已经把 NF/NE 收进同一侧，更不能再往这侧塞第二问。

半句 B 留下的是看见层那截，不是整句 B。078 要锁的是兑换关系：承认 077 ≠ 复活 A/C/D，也 ≠ 选了整句 B。这不是 062–065 的复述；那一轮锁的是「四个口不能当宿主」。本轮锁的是「改叫标签之后，那三个口仍不能当宿主」。

**Judgment / Verdict**：real-problem。方案可以叫看见层的标签；A / C / D 整句仍死；B 整句仍死。
