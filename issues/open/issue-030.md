**Class**: boundary

**Layer**: Protocol / 判定对象与词表

## Verifier Discovery

029 钉死「办不了 + 是/不是」会翻面。本 issue 钉替代结构。031 才把要不要看见、用哪句中文交回用户。

### 协议里已经有不可两读的那一格

`spec/alg/authority.md` §1：

> Authority Agent 只解决“标准是否确定”，不判断某个实际输出是否满足用户要求。

§8.2：能力/边界问题必须是「有没有这个能力 / 属不属于职责」，不得写成「当前输出对不对」。

§8.3 三类 statement 已经具名：

```text
职责外（产品没有该能力/不在职责范围）
职责内能力缺失（应具备但未实现/表达不了）
职责内正常
```

`fulfilled.md` §2.2 把「功能本身未实现」压进没办成，不区分原因。
013 Consensus：这三类是挑 F/NF/NE 的隐藏中间量，挑完就吃掉。
015 Consensus：若有第二问，只能与三态正交，标出定位内当前明确尚未支持的那一格，不回写 status。
022 Consensus：第二问的判定对象必须是产品事实。
023 Consensus：只许区分「这次交付失败」和「职责内今天就办不了」；2×2 不是对外词表。
024 Consensus：还活着的是能单独指认「职责内、今天就办不了」的家族，不是「办得了吗」五个字。

所以缺口不是「协议里没有这一格」。缺口是：上一轮把它翻译成了比它更大的口语「办不了」。

### 一件产品事实（和第一问同级）

第一问的对象：这一次，用户要的事给到了没有。
第二问的对象：用户要的这种事，是不是「产品定位内、当前尚未具备」。

两问对象不同：

| | 第一问 | 第二问 |
|---|---|---|
| 看的东西 | 这一次的交付结果 | 当前产品有没有这类办法 |
| 时间 | 这一次 | 当前产品（不是这一次） |
| 动词 | 办成 / 给到 | 具备 / 尚未具备 |
| 正格 | 办成了 | 定位内尚未具备 |

「定位内」是正格的定义前提，不是对外再问一遍「该不该管」。和「办成了」已经要求职责内是同一手法：`fulfilled.md` §2.1 把职责内写进定义，题面仍只问办成了没有。

022 已占用「材料够不够」当第一问内部第二层。第二问若存在，不得再叫第二层，只能是与三态正交的一层。

### 词表必须具名，不能是是否

是否是对句子点头。句子一漂，是否跟着漂。029 已证。

封闭三词：

```text
定位内尚未具备
  这种事落在产品定位内，当前产品没有完成它的办法。
  两个条件同时成立才进此格。少一条就不得进。

不得叫「定位内尚未具备」
  不是另一种产品事实，是正格的补集。只准下面这些进来：
  - 这类办法产品里已有，这一次没用好 / 没用对（漏做、做错）
  - 这种事不在产品定位内（查天气；已裁职责外的车牌）
  - 用户给的不是可办对象（格式外编号、输入坏）
  - 事还没成形，谈不上具备不具备

材料不够，判不了这一点
  无法确定上面两格哪一格。
  不得用此格装长期的定位内缺口（013 / 015 已死）。
```

014 已说轴 2 不必先做成完整划分。补集保持补集，不升成「缺口在哪一侧」。
024 已死：把 Authority 三类前缀再问成对外三值。本词表只有「是不是那一格」，没有把职责外 / 职责内正常公开成并列主值。

### 边界对照（换语境也不得翻）

| 例子 | 办成了没有 | 第二问 | 为什么 |
|---|---|---|---|
| 正常办成 | 办成了 | 不得叫 | 办法已有，且这次用上了 |
| 漏了姓名 | 没办成 | 不得叫 | 办法已有，这一次没用好。会话语境也不得改口 |
| 投保年缺口 | 没办成 | 定位内尚未具备 | 定位内，当前没有完成它的办法。不预判「去年」个案，只作形态例 |
| 格式外编号 | 说不清 | 不得叫 | 不是缺一种功能，是对象不成立。009 / 014 已否「本可支持」 |
| 查天气 | 说不清 | 不得叫 | 不在产品定位内。不是「尚未具备」，是不该具备 |

「产品该能做、这回没做到」= 第一问的没办成，不得进正格。
「该具备但当前做不到」和「受限于因素就是做不到」今天仍是同一格（023），本轮不切。
「尚未具备」不是「正确承认尚未支持」。022 杀死的是「承认」这层检查项，不是「尚未具备」这个对象。

### 题面约束（防再漂）

结构锁这些，不锁对外终句：

1. 不得与第一问同用「办」当第二问动词
2. 若出现「今天」，必须钉死为「当前产品」，不得读成「这一次」
3. 不得用是/不是当主词表
4. 正格名称必须把「定位内」和「尚未具备」一起写上；只写「还没有 / 办不了 / 不支持」不算
5. 听懂不得依赖承认 / 尽力 / 位置 / 处置（022）

### 可证伪

- 漏了姓名 与 投保年缺口 不得同格
- 投保年缺口 与 格式外编号 / 查天气 不得同格
- 同一案子从会话语境换到产品语境，第二问状态不得变
- 只读第一问的「没办成」，不得能写出第二问的正格

任一题面或词表违反以上四条，即未达本轮无歧义。

### 不是什么

- 不宣布「定位内尚未具备」是对外终名
- 不把 2×2 画成对外问卷
- 不预填去年 / 称谓 / 格式外算不算单号
- 不改 fulfilled §2.2，不加第四态

### Reasoning

029 杀掉的是过大的谓语。030 要钉的对象确实在协议里：§8.3 的 `职责内能力缺失（应具备但未实现/表达不了）`。缺口不是「没有这一格」，是上一轮把它译成了比它大的「办不了」。这一层我同意。

但 issue 原文把三件不同的东西焊在一起了，不能整包收下。

**1. 没有把三类前缀走私回对外三值——如果锁成「一格投影」。**

024 杀掉的是「职责外 / 职责内能力缺失 / 职责内正常」并列当对外主值。015 / 023 还活着的做法是：只标出那一格，补集保持补集。030 的三词（正格 / 不得叫这个名字 / 材料不够）是「是不是那一格」，不是把另外两个前缀公开成并列主值。014 已说轴 2 不必先做成完整划分。走私指控在这个结构上不成立。

反过来：若把「定位内尚未具备」当成评测员要当场重判的对外主问，评测员必须先判定位内、再判尚未具备，这就是把 §8.2 的能力/职责问题再问一遍。那才是 024 禁的。能力事实在本协议里由 Authority 裁（§8.2），不是新开一条常识轴。第二问若存在，是已经裁完的 statement 上的一格投影，不是新的三类问卷。

**2. 「定位内尚未具备」四个字本身仍两读，未过章程三条。**

协议格子不可两读，不等于这四个字不可两读。029 的标准是：失败不在定义没写细，在题面请人读成另一问。同一标准套回来：

- 「尚未具备」可读成「这一次还没给到」→ 漏姓名进正格，第二条死。
- 丢掉「定位内」只听「尚未具备 / 没有」→ 查天气进正格，第二条死。
- 「定位内」写进正格名字，等于把 023 要求隐藏的「该做」公开成评测员先答的合取。§2.1 把职责内写进「办成了」的定义，题面并不让人先念「职责内」。这个类比 030 自己写了，但选用的名字没有遵守类比。

所以：对象是那一格，成立。把「定位内尚未具备」写成已经无歧义的对象名 / 词表正名，不成立。它只是理事会内部手柄。当问题干贴出去，它过不了换语境测试。031 不得把它升成终句，030 自己也不得假装它已经过关。

**3. 原文对照表有一个协议洞。**

§8.3 明文：`职责内能力缺失` 且实际达成 → F。格子说的是这类办法当前缺，不是这回一定没办成。030 表把「正常办成」一律写成「不得叫」，把「办法已有且这次用上了」和「办法仍缺但这次绕过/碰巧给到了」焊死。若第二问真是和第一问同级的产品事实（022），Q1=办成了不能自动推出不得叫。023「只区分两种失败」是失败形态对照，不能回写成「办成了 ⇒ 不是那一格」。

**4. 是否词表必须死，具名必须是结构约束。**

029 已证：是否只放大含混谓语。正格必须是「两个条件同时成立」的那一格，只写「还没有 / 办不了 / 不支持」不算。这是对以后任何终句的约束，不是本轮代拟终句。
