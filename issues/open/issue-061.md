## Verifier Discovery

用户说：先别改东西。也问了：用户怎么看到这个东西，因为现在前端只能看见 fulfilled。

这两句要拆开。

「先别改」是红线：本轮不改 schema、不改前端、不改协议正文、不加字段。
「怎么看到」是位置问题，060 已经给出挂点：以后若看见，挂在矩阵行上、Status 旁边。

不能把「现在看不见」兑换成下面任一动作：

```text
给 fulfilled 加一个枚举值
让 Judge 再填一格
只在没办成的行上画标记
本轮先改主表「状态」让人看见
```

046–048 已否前三件。第四件是 060 否掉的看见点。

### 现在看不见，说明什么

只说明第二问还没有出口。不说明：

- 它只属于没办成
- 它必须并进 fulfilled 才能存在
- 它必须先改表才能把位置说清楚

`product-function.md` §9 已经把「现在不做」写死：不改 Judge prompt、不改结果表、不改归因、不改 authority 词表、不上线新字段。
本轮沿用，不把它重新解释成「所以还不知道放哪」。

### 仍停住、本 issue 交给项目

1. 要不要现在就让人看见第二问
2. 看见的话，对外那一格叫什么（不得宣布采用「立住了 / 没立住 / 现成有」）
3. 现在改不改 schema / 结果表
4. 去年 / 称谓 / 格式外（与本轮无关，继续停）

角色可以锁 060 的挂点。角色不能替用户打开那一格。

### 可证伪

1. 若位置不先改前端就无法被说清，本 issue 把「看见」和「落点」混成了一件事，应打回 060。
2. 若「先别改」意味着连四层落点都不能锁，本轮章程的 Done 本身不成立。
3. 若对手认为现在就必须改表，才能避免「用户永远只看见 fulfilled」，那是 §4，应维持 escalate，不得由角色改代码。

### 不是什么

- 不是请用户再写一句对外题面
- 不是请用户把所有形状列完
- 不是本轮实施派生列

### 请对手挑战

- 用户连续两轮在问「放哪 / 怎么看见」。只锁落点、不改界面，会不会被读成没回答实现？

- 本 issue 是否应直接 `escalate-to-project`，不要伪装成还可以在协议里再辩一轮？

### Reasoning

用户两句要拆开，拆完就没有第三轮协议可辩。本 issue 的正确终点是 escalate-to-project，不是再锁一条「定义」。

**1. 「先别改」不是「四层也不能锁」。**

可证伪 2 不成立。章程自己把「实现」定义成位置图：从哪份裁口读、对象跟哪一行走、四层怎么拆、以后若看见挂哪一格。058–060 答的是这个。若「先别改」连落点都不许锁，本轮 Done 自杀。落点可以锁，出口不能动。

**2. 「人怎么看见」已经被答完了：现在看不见；以后看见挂 060 那一格。没答的是要不要打开。**

可证伪 1 不成立。位置不先改前端也能说清：缺的是出口，不是定义；规范格子在矩阵行上、Status 旁边；主表「状态」永远不能兼答。人现在只看见 fulfilled，是因为那一格还不存在，不是因为第二问属于没办成。

这不是没回答实现。怎么算（058）、跟哪一行走（059）、四层和规范格子（060），都是实现位置。用户连续两轮在问「放哪 / 怎么看见」，本轮该交的就是这张图。把图画成一列上线的字段，才是没按「先别改」做事。

**3. 主表对照「互有对错 / 过严」也改不了本 issue 的终点。**

过严 / 互有对错是两轴对照后的读法（product-function.md §6），不是状态，也不是案件表「状态」该兼的词。若项目以后要在主表上对照，只能投影 059/060 已经按行算好的东西，不能把主表芯片改成第四态。要不要做这块对照面，仍是 §4.1，角色不能为了「否则没用」去改主表。可证伪 3：若对手认为现在就必须改表，应维持 escalate，不得由角色改代码。

**4. 所以 061 不要再伪装成协议题。**

046–048 已否：给 fulfilled 加枚举、让 Judge 再填、只在没办成的行上画标记。060 已否：本轮先改主表「状态」让人看见。这些死路不必在 061 再辩一次。留下的四件都是章程 §4 项目决定。角色可以锁挂点，不能替用户打开那一格，也不能代拟对外中文。
