# Issue #051: 这张嘴是充分性测试，不是履约一般定义，也不是换皮覆盖门

**Class**: generalization

**Status**: verifier-raised
**Evidence**: code-analysis
**Layer**: `field_sufficiency.decide`
**Cases**: 红莲保单 / 唐诗颖生存金 / 李明的重疾险 / 李明重疾险 / 查一下杨杰

## Verifier Discovery

用户担心：看似没有规则化，本质其实是规则化；扩散到别处容易失败。
姓名只是要处理的问题之一。

042 已经锁死：覆盖门把 Q2 定义成「残句为空 + 必须有身份字段」。
那不是原则。本轮若再把「值等于整句」说成覆盖门的特例，042 回潮。

本轮的形状：

```text
只在充分性打中时说话。
新句子来了，打不中就 inherit。
不新开题型，不新开虚词，不新开年龄/产品/保费。
```

`decide()` 对任意输入只问：

1. 能不能读出恰好一对字段/值
2. 值是不是整句
3. 该字段有没有授权标准
4. 若有，Q1 过不过

它不看 `role`，不看残句，不剥「的 / 一下 / 岁 / 以上」，不点名样本 ID。

所以：

- 「红莲保单」交姓名=红莲 → 值不是整句 → inherit
- 「唐诗颖的生存金有没有领取」交姓名=唐诗颖 → inherit
- 「李明的重疾险」交姓名+产品 → 不是单字段 → inherit
- 「李明重疾险」同样 inherit（覆盖门会抬；本嘴不抬）
- 「查一下杨杰」值不是整句 → inherit（禁止靠剥虚词优化）

inherit 不是漏。它是所有还没被授权说话的情况的正式去处。
「能覆盖所有可能出现的情况」= 每一格都有去处，不是 = 全部改判对。

授权字段只有 `searchClientName` 和 `clientNo` / `polNo`。
姓名尺读业务源，不用 341 集 A 投影，不抄地址 hint 表。

## 可证伪

1. 若 `decide` 读取混合包 `role` 或样本 ID，本 issue 未修。

3. 若红莲保单 / 生存金 / 李明的重疾险 / 李明重疾险被这张嘴改成 fulfilled，本 issue 未修。
