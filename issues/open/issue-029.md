# Issue #029: 「今天就办不了吗 + 是/不是」题面必然换语境翻面

**Class**: boundary
**Severity**: high
**Status**: verifier-raised
**Evidence**: code-analysis

## Verifier Discovery

用户否掉上一轮甲/乙：「今天就办不了吗」有歧义和语境偏差；是/不是会导向另一个结果。

本 issue 只钉题面为什么必然漂。无歧义对象在 030。交给用户的决定在 031。

### 协议里第一问用的动词

`spec/alg/fulfilled.md` §1：

> 我们：评测系统（Judge），只看一件事——系统有没有帮用户办成想办的事。
>
> 第一层：用户要的事办成了没有？

§2.2 没办成「不区分原因」，并把「功能本身未实现，但用户期望已提出」收进没办成。

所以「办成了 / 没办成」已经占用「办」。再问「办不了吗」，听的人没有任何理由换一个对象。

### 「今天」在中文里有两个时间

- 这一次：今天这趟没办成
- 当前产品：今天这个版本没有这件事

上一轮题面把两个时间叠在一个字上。换评测员的语境，答案就会翻。

### 碰撞：同一题面，两种语境，两套结果

只问「今天就办不了吗」，答是/不是。

会话语境（把「办不了」读成「这回没办成」）：

| 例子 | 是/不是 | 破了哪一关 |
|---|---|---|
| 漏了姓名 | 是 | 漏做和「定位内尚未具备」成了同一个词 |
| 投保年缺口 | 是 | — |
| 格式外编号 / 查天气 | 是 | 投保年缺口和格式外/天气成了同一个词 |

产品语境（把「办不了」读成「产品没有」）：

| 例子 | 是/不是 | 破了哪一关 |
|---|---|---|
| 漏了姓名 | 不是 | 过了漏做那关 |
| 投保年缺口 | 是 | — |
| 查天气 | 仍可能是 | 正格吞掉职责外 |

两种语境都不能同时过章程 §1 的三条。所以失败不在「定义没写细」，在题面自己请人读成另一问。

### 是/不是放大了含混谓语

对一个已经两读的句子点头或摇头，得到的不是第三个稳定事实，是评测员自己选的那种读法。
用户说的「在歧义和语境下面都有可能引导向另外一个结果」，就是这件事。

022 已锁：听懂第二问不能依赖承认 / 尽力 / 位置 / 处置。
本 issue 补一条：听懂第二问也不能依赖评测员自己选「今天 / 办」的哪一种读法。

### 不是什么

- 不是重开 024 去宣布采用另一句口语
- 不是说「办」这个字永远禁用；第一问继续用「办成了没有」
- 不是重判漏姓名 / 投保年 / 格式外的对错

### 可证伪

若存在一种读法，让「今天就办不了吗」的是/不是把漏做和投保年缺口收成同一个词，或把投保年缺口和查天气收成同一个词，则该题面未达本轮无歧义。甲/乙已经失败。

### 未消元

- 换成别的动词是否就够，见 030
- 对外终句仍不由本 issue 选定

### Investigation

重读，不抄 verifier 转述：

- `spec/alg/fulfilled.md` L16：评测系统「只看一件事——系统有没有帮用户办成想办的事」。
- 同文件 L23–25：第一层「用户要的事办成了没有？」；第二层「手里的材料够不够回答第一层？」——「第二层」已被材料前提占用。
- 同文件 L38–48 §2.2：没办成「不区分原因」，并把「功能本身未实现，但用户期望已提出」收进没办成；「功能未实现」也是没办成，不降级为说不清。
- `spec/alg/authority.md` L18：Authority「只解决标准是否确定，不判断某个实际输出是否满足用户要求」。
- 同文件 L487：Authority 只裁决「有没有这个能力 / 属不属于职责」，不裁决「本次输出是否达标」。
- 024 Consensus：还活着的是能单独指认「职责内、今天就办不了」的家族；「办得了吗」属于这个家族，但不能当对外主问——它和「办成了没有」叠音。
- 023 Consensus：若把格式外、职责外、说不清也叫「办不了」，就是 014 已否的大筐。
- 022 Consensus：听懂第二问不能依赖承认 / 尽力 / 位置 / 处置。
- 章程 §1 三条：换语境不翻面；漏做 ≠ 定位内尚未具备 ≠ 格式外 / 查天气；不能靠「办成了没有」答完。

本轮无 runtime 可复跑。碰撞按章程 §5 做题面换语境测试，不重判个案对错。

### Reasoning

不是「措辞不顺」。是题面和 `fulfilled.md` §1 / §2.2 发生了真的词法碰撞。

「办」在第一问已经被占成交付动词。§2.2 又把「功能未实现」压进「没办成」、不区分原因。所以「办不了」在协议内部首先是「没办成」的口语否定，不是「职责内能力缺失」的专名。再问「办不了吗」，听的人有一条现成的、已经被第一问训练过的读法；他们不是没有换对象的可能，而是题面没有给出必须换对象的理由。verifier 写「没有任何理由」过重，但结论成立：题面在请人读成另一问。

「今天」独立再滑一次：这一次会话 / 当前产品。是 / 不是 只对已经两读的谓语点头或摇头，不创造第三个稳定事实。这就是用户说的「在歧义和语境下面都有可能引导向另外一个结果」。

按章程三条测，不是按「训练过的评测员能不能读对」测：

1. 会话语境（办不了 = 这回没办成）：漏姓名 / 投保年缺口 / 查天气 都是「是」。三案一词，第二条死。
2. 产品语境（办不了 = 产品没有）：漏姓名变「不是」，同一案子换语境翻面，第一条死；查天气仍可能是「是」，正格吞职责外，第二条仍死。
3. 存在一种被定义按住的读法（今天=当前产品，办不了=只指定位内能力缺失）能把三案分开。这不能救题面。029 自己的标准说对了：失败不在定义没写细。024 已经写过，过验收只证明家族，不证明这几个字能贴出去。「今天就办不了吗 + 是/不是」连家族验收都过不了——它不强制那一种读法。

所以：不是重开 024 去另找一句口语；是钉死这条题面 + 是否词表不得再当第二问。办 继续合法地留在第一问「办成了没有」。
