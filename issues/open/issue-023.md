# Issue #023: 「办得了吗」必须切开，否则会偷走 fulfilled 的题

**Class**: boundary
**Severity**: high
**Status**: verifier-raised
**Evidence**: code-analysis
**Layer**: Protocol / 切面
**Cases**: 只作形态举例。不重开 007 / 009 / 014。

## Verifier Discovery

用户自己试的角度是：「这件事，这个产品现在办得了吗？」并立刻感到危险——能不能做好像有两种，且会和 fulfilled 混在一起：

1. 产品应该得能做但是没做到
2. 当前受限于一些因素就是做不到（用户说可能切得不准）

本 issue 只切这一刀。014 已经钉过：共享「不能换 F」，不共享「尚未支持」。这里要把用户的两种「能不能」接到协议已有的格子上，防止第二问把 fulfilled 再问一遍。

### 协议已经怎么切的

`fulfilled.md` §2.2 没办成不区分原因，并且把「功能本身未实现，但用户期望已提出」写进没办成。§3 第二步把「属不属于职责、系统有没有这能力」交给 Authority，再回第三步看实际交付。

`authority.md` §8.3：

- 职责外 → 说不清（职责外）
- 职责内能力缺失 + 期望未达成 → 没办成（不得降 NE）
- 职责内正常 → 按交付判

`fulfilled.md` D5：字段在清单但实际不支持，必须先问「该不该支持」；问不了是说不清，不是自动没办成。

`authority.md` L467：输入坏 / 完全无关不走 Authority。

014 Consensus：用户原句只覆盖 α 形态；β（事没成形）和 γ（职责外）不得使用「定位内尚未支持」；去年不得默认 α；称谓未分派。

### 用户的两种「能不能」，其实不是同一根轴上的两格

把它摊开，是两问的组合，不是「能不能」自己切两刀：

| | 今天做得到 | 今天做不到 |
|---|---|---|
| 该做 | 交付问题：办成了 / 没办成。漏条件、改错值、该出没出，全在这里。这是 fulfilled 的题。 | 产品事实：认这是自己的事，但今天明确办不了。这是新格。需求未达成仍可 NF。 |
| 不该做 | 不应出现（产品不认的事却做得到，是越权，不是「办成了」） | 职责外 / 完全无关。已有 NE。 |
| 该不该还说不清 | — | 依据不充分。已有 NE。D5 落这里。 |
| 事没成形 | — | 输入坏。已有 NE。不是「现在办不了」。 |

所以：

- 用户说的第 1 种「应该能做但是没做到」，若是指「这类事今天做得到，但这回漏了 / 做错了」——这是上表左上角，是 fulfilled，第二问不得再收。
- 用户说的第 1 种若是指「产品该具备、但从来没做成这维」——这是右上角，和用户说的第 2 种「受限于因素就是做不到」在今天看来是同一格：该做 × 今天做不到。差别是「以后该不该补」，那是产品路线，不是评测第二问现在必须切的刀。
- 用户说的第 2 种若把格式外、职责外也收进去，就会再次制造 014 里的大筐。

「尽力了」会把整张表右边（做不到）加上事没成形，收成一个词。这就是它看起来顺、但不能当主抽象的原因。

### 第二问只允许松开一处压缩

fulfilled §2.2「不区分原因」必须保住：漏条件、改错值、没交付，仍然都叫没办成。

第二问若存在，只允许松开这一处：

> 没办成，是因为这次交付失败（左上），还是因为今天这事就办不了（右上）？

不允许再松开：漏 vs 错 vs 改；也不允许把右上、职责外、输入坏合成「办不了」。

### 不是什么

- 不是裁定去年该不该做（章程 §4，D5）。去年只是右上角的形态候选，本轮不确认。
- 不是把 Authority 三类前缀直接当出口。前缀是隐藏中间量（013 Consensus）。
- 不是让 Q2 回答「该不该补到路线图」。那是产品决策。

### 可证伪修复（原则）

任一「办得了吗」定义，若让「这次漏了姓名」和「今天就办不了投保年」落进同一格，则偷走了 fulfilled。若让「办不了投保年」和「P07000000」落进同一格，则未修 014。

### 未消元

对外问句见 024。右上角要不要再拆「该补 / 不该补」，本轮不拆。

## Improvement Proposal

**Problem**: 「办得了吗」若不先切开，会把 Q1 的交付失败和「今天职责内就办不了」收成同一个词；切过头又会把 Authority 前缀整表公开。

**Proposed Change**: 锁切面，不锁对外句子，不改 `spec/alg/fulfilled.md` §2 三态。

**Design**:


**Implementation Steps**:
