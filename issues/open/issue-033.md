## Verifier Discovery

032 钉死：030 的定义还在用第一问的单位。本 issue 钉替代结构。034 才写哪些决定仍停住。

用户要的层级是 `fulfilled.md` 那种：只看一件事、有单位、有不看、有封闭三态。不是一句更顺的口语。

### 协议里已经分开的两件事

`fulfilled.md` §1 把 Judge 收成一件事，并且自己写了第二层：

> 第一层：用户要的事办成了没有？
> 第二层：手里的材料够不够回答第一层？

`authority.md` §8.3 把能力/职责的结论类型已经具名：

```text
职责外
职责内能力缺失
职责内正常
```

消费规则：

```text
职责内能力缺失
    → 不强制改状态；结合实际交付：
        期望未达成 → 没办成
        实际达成   → 办成了
```

所以：

1. 「这种事产品里现成有没有」本来就不是「这一次给没给到」。
2. 现成没有，这一次仍可能给到（§8.3 明文）。
3. 现成没有，也不能改口说成办成了，或改口说成说不清（§2.2 / §8.3）。

第一问已经有一条「不看」：不看产品里现成有没有，来改写给到了没有。
第二问缺的是镜像的那一条：不看这一次给没给到，来改写现成有没有。

本轮只许留一套。按 oracle：

- 同级：第二问必须和「办成了没有」一样，是一件独立的产品事实（022 / 015 的正交）。
- 所以 023「只区分两种失败」不能再当第二问的定义。它只是两问交叉之后、当第一问=没办成时的对照表。
- 015「承认处置」不能再当第二问的定义。承认是第三问，022 已杀。
- 023「该做保持隐藏」仍然活：职责内是进门前提，不单独对外问「该不该管」。这和第一问一样——「办成了」的定义里有职责内，题面并不先问职责内。

### 正确结构（协议手柄，不是对外题面）

```text
只看一件事——用户要的这种事，产品里现成有没有做成它的那一档。

单位（少一个就串问）：
  · 这种事（从这一次请求里认出来，不从这一次交付里认）
  · 产品里现成的那一档（站立的产品事实，不是这一次有没有路子）

不看：
  · 这一次给没给到
  · 这一次承不承认
  · 这一次尽没尽力

三态：
  现成有        职责内已经确定，并且产品里现成有做成这种事的那一档
  现成没有      职责内已经确定，并且产品里现成没有做成这种事的那一档
  现成说不清    必须写清差在哪儿：
                  职责外 / 完全无关
                  对象未成形 / 输入坏
                  依据不充分（分不清「现成没有」还是「现成有、这一次没用」）
                  不得用「说不清」装长期现成没有

隐藏前提（不单独对外问）：
  职责内由 Authority 先裁，和第一问的「办成了必须职责内」同一层。
  评测员不得先答「该不该管」再答第二问。
```

「现成有 / 现成没有 / 现成说不清」只是本轮内部手柄，用来证明三态能按单位切开。不是对外题面，也不宣布采用这六个字。

### 对照只作形态，不重判、不预填去年 / 称谓

| 例子 | 办成了没有 | 第二问 | 挡住「现成没有」的是哪一条 |
|---|---|---|---|
| 漏了姓名 | 没办成 | 现成有 | 产品里现成有按姓名搜；这回没用好 |

最后两行保留 030 对 023 对照表的修正：第一问办成了，不能自动排除「现成没有」。这不是新发明，是 `authority.md` §8.3 原文。

023 的 2×2 降成交叉表：

```text
                 现成有              现成没有
办成了           正常办成            现成没有但这次给到了
没办成           漏做 / 做错         用户说的「尽力了」那一格
```

交叉表不是第二问，也不是新坐标系。用户最早说的「尽力了」只是左下/右下里的一个观感，不能当主问（022）。

### 为什么这套不会换语境翻面

答第二问时，评测员被禁止看这一次交付。于是：

- 把「今天 / 办 / 完成 / 办法」读成「这回没办成」的路被堵死，因为那条路必须看交付；
- 是 / 不是 不再对含混谓语点头——谓语已经被单位钉死；
- 漏做进不了「现成没有」，因为它的产品那一档现成有；
- 查天气进不了「现成没有」，因为它差在职责外，只能走「现成说不清（差在：职责外）」。

若有人把「现成没有」听成「这回没给到」，不是题面再漂，是他违反了「不看」。这和把「办成了」听成「态度好」一样，是违规读法，不是定义两读。

### 不是什么

- 不是第四态，不回写 `status`，不进 overall
- 不是把 Authority 三类前缀再问一遍
- 不是 IT 字段审计，不是 `is_supported=false`
- 不是「正确承认尚未支持」
- 不是「尽力了吗」
- 不是「今天就办不了吗 / 办得了吗」
- 不是宣布采用「现成有 / 现成没有」当正式题面

### 可证伪

1. 只看这一次交付，写得出「现成没有」→ 结构失败。
2. 漏做和投保年缺口落到同一格 → 结构失败。
3. 投保年缺口和查天气 / 格式外落到同一格 → 结构失败。
4. 第一问=办成了，且 Authority statement=职责内能力缺失，却不许标「现成没有」→ 结构失败（与 §8.3 冲突）。
5. 把 023「两种失败」或 015「承认」重新写成第二问的定义 → 本 issue 被越权。
