# Issue #065: 「新增 judge 结果标签」若是再让这张嘴写一个词，也不能当宿主

**Class**: architecture
**Severity**: high
**Status**: verifier-raised
**Evidence**: code-analysis
**Layer**: 结果口 B / 新增 judge 结果标签
**Cases**: 只作落点碰撞，不重判。

## Verifier Discovery

用户本轮点名：应该新增一个 judge 结果的标签，还是 3 扩 4，还是放到 NE。

三句话并列时，「新增一个 judge 结果的标签」指的是：在判定已经写下的那份结果上，再多一个由判定写出的词，用来回答第二问。本 issue 只钉这个口。它不是 060 说的「以后若看见，在同一行旁边另开一格」。

### 判定现在写出的结果是什么

`impl/core/schema/judge.py`：

```text
JudgeFulfillmentAssessmentOutput.status
```

模型可写的评估字段仍只有这一格。`authority_tool_call_ids` 是引用，不是第二问答案。

`spec/info-volume.md`：judge 只产 fulfillment，不产第二个判定维度。

`spec/alg/product-function.md` 开篇：

> 不进入 Judge 产出，不进入结果表词表。

同文件 §7.2：让 Judge 再填一个新标签来回答本协议 ✗。

047 Consensus：第二问不是同一轮 Judge 再填。刚写了办成了，下一句就倾向写成立住了。那是对齐，不是产品事实。

所以「新增一个 judge 结果的标签」若按字面做，就是再开一张嘴。058 已经锁过：第二问是读已经写下的前缀，不是再判一类。

### 和另外三个口是同一类错

用户并列的四个口，其实都假设：第二问要住进第一问那份结果的词表里。

| 点名口 | 实际在改哪张嘴 | 本轮 |
|---|---|---|
| A. 只是 NF 补充 | 第一问的没办成 | 062，不能当宿主 |
| C. 3 态扩 4 态 | 第一问的 status 词表 | 064，不能当宿主 |
| D. 放到 NE | 第一问的说不清 | 063，不能当宿主 |
| B. 新增 judge 结果标签 | 第一问那份结果上再让判定写一个词 | 本 issue |

B 看起来比 C/D 干净：status 三词不动。但它仍让判定再写一次。写的人是刚答完「办成了没有」的同一张嘴。047 的改口不是气氛问题，是同一轮两个出口会互相对齐。

前端现在只能看见 fulfilled。给判定多一个可写标签，下一步几乎必然是：这个标签也画进「状态」，或者只在没办成行显示。前者回到 064，后者回到 062。标签本身解决不了看见层。

### 不要和「以后旁边那一格」焊在一起

060 Consensus 活着的家族是：

```text
以后若存，只物化同一份派生读
以后若给人看：同一条期望上，办成了没有旁边，另开一格
不是 Judge 再填
不是 schema 新枚举
不是本轮批准打开
```

那一格如果以后打开，读者会叫它「一个标签」。本 issue 不批准打开它，也不把它改名为「judge 结果标签」。

两件必须分开：

| | 本轮点名的 B | 060 以后若打开的那一格 |
|---|---|---|
| 谁写 | Judge 再填 | 读已经裁完的前缀 |
| 进不进 prompt | 进 | 不进 |
| 现在做不做 | 不做 | 仍交章程 §4 |
| 算不算「新增 judge 结果标签」 | 算 | 不算。那是派生阅读，不是判定产出 |

若把 060 的那一格写成「所以 B 口合法」，就是用看见面偷换判定产出。048 已经禁止这种批准。

### 四个口之后，宿主是什么

按 fulfilled 的定位：第一问那三个词只答办成了没有。第二问不进这三个词，也不进判定再写的第四个词。

计算位置继续是 058 的读。规范格子继续是 060 的兄妹格。打开与否继续是 061 / 章程 §4。

本轮角色不得把上面这段写成「请先加字段」。

### 不是什么

- 不是批准派生列上线。
- 不是说「结果对象上永远不许出现第二问」。以后若存，那是物化同一份读，不是新判定。
- 不是让评测员重判三类前缀来填标签。

### 可证伪

同时成立才算「新增 judge 结果标签能当宿主」：

1. 这个标签由同一轮 Judge 写出；
2. 它不回写 `status`，也不只在 NF 后出现；
3. 刚写了办成了的那张嘴，不会用这个标签去对齐产品事实。

1 和 3 互相打架。现行判定只有一张嘴。所以 B 口不能当宿主。

## Proposed Change

Consensus 只锁：

1. 「新增一个 judge 结果的标签」若指判定再写一个词，不能当宿主；
2. 不得把 060 的派生兄妹格改名为 B 口、当成已经批准；
3. 四个点名口都不能当宿主；打开看见层仍交章程 §4。

不改 schema，不改前端，不宣布对外中文。
