## Verifier Discovery

032–034 已经锁了两问差在单位。本 issue 只钉：033 把单位写成「认哪一类 / 那一档 / 四例对照」之后，评测员拿到的是一张预置类型表。这踩中本轮章程的「不要有规则化」，也假覆盖。

替代原则在 040。仍停住的项目决定在 041。

### 033 原文里的类型门

033 Consensus 第 4 条：

> 认「这种事」是哪一类，只准看这一次请求。

再加上对照表：

| 例子 | 第二问 |
|---|---|
| 漏了姓名 | 现成有 |
| 投保年缺口 | 现成没有 |
| 格式外编号 | 现成说不清（对象未成形） |
| 查天气 | 现成说不清（职责外） |

再加上单位里的「那一档」。

三件叠在一起，手续变成：

```text
先把请求分进类型 → 再查这一类有没有那一档 → 新形状就加一行
```

### 为什么这不是 fulfilled.md 那种原则

`spec/alg/fulfilled.md` §1 认的是「用户要的事」，不是「用户要的事属于哪一类」。

§2.2 没办成「不区分原因」。漏条件、改错值、功能未实现，走同一个出口。
它没有先建一张「漏做类 / 能力缺失类 / 天气类」再查表。

§2.3 的「差在哪儿」写在说不清后面，是理由，不是进门分类。

033 的「哪一类」把第一问里「认用户要什么」偷换成「把用户要的事编进预置类型」。
前者是读请求。后者是规则化。

### 假覆盖

章程把「能覆盖所有可能出现的情况」定义成全函数，不是把例表写长。

四例写全了，也盖不住这些形状（只作针，不升成新行）：

- 用户要的是合取（姓名且年）
- 别的表面才有，这个产品没立
- 文档有，这一次从来没交过
- 在建 / 半成品
- 这个租户没有，但是一次权限事故 ≠ 产品没立
- 用户要的事两可
- 相邻近义
- 只立住一部分
- 以前有、现在拆了
- 完全没见过的新形状

若评测员只能靠「再加一行类型」才能落格，033 的操作化就不是覆盖，是一张会过期的表。

### 和已锁五条的关系

本 issue 不否下面这些：

- 两问同级，差在单位
- 答第二问不看这一次交付
- 「没立住」进不了漏做，也进不了职责外 / 对象未成形
- 第一问办成了，不能自动排除「没立住」
- 2×2 只是交叉表

否的是 033 第 4 条里「认哪一类」和单位里「那一档」的操作化。
格子还在。类型门退休。

### 不是什么

- 不是重开 032：030 定义句仍死
- 不是重开 029：那句「今天就办不了吗」仍死
- 不是说 033 找错了单位差
- 不是把四例的对错重判一遍
- 不是宣布采用「立住了 / 没立住」当对外题面

### 可证伪

1. 若存在一种合法读法，让人必须先把请求分进预置类型才能答第二问，则 033 操作化未达本轮「不要有规则化」。
2. 若存在一种未在四例里的形状，必须加新行才能落格，则 033 操作化未达本轮「覆盖」。
3. 若「认哪一类」被证明只是 fulfilled.md §3「用户要什么」的同义反复，且不含预置类型，则本 issue 失败。

### 未消元

- 正确原则见 040
- 要不要看见、改不改表，见 041
