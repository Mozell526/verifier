## 先答疑惑

不是。它不是 not_fulfilled 的原因说明项。排除不是「分开更干净」，是放进去会改掉你已经锁住的东西。

「像」是真的。现行办成协议已经把「功能本身未实现」写成没办成的一种理由。原因栏现在也在解释「刚才那个词为什么是这个词」。所以你会觉得它像原因。像，不等于它就是那个身份。

放进原因栏会改掉：

1. **单位。** 这块东西看「这件事 × 产品事实」，不看这一次给没给到。原因栏看的是这一次为什么没办成。放进去，产品事实变成失败原因。
2. **出口。** 你锁的是立住了 / 没立住 / 说不清。「立住了」不能当没办成的原因。放进去，三态被收成「没立住」一个原因值。
3. **办成了也不能自动排除没立住。** 职责内能力缺失、这一次却给到了，按办成协议算办成。原因栏在办成了时写不下没立住。
4. **对象。** 已锁对象仍是那一件期望。现行原因栏是整案一句。塞进去是切粗。

「只在没办成时才给人看」是看见时机，不是身份。时机仍停住，不能拿来把原因栏救活。

把三态后缀进原因栏也救不了：读者要么听成自相矛盾，要么把「立住了」听成没办成的原因。单位和出口还是被改掉。

## 方案

```text
用户认得的这一块，出口单独开一格。
这是点名里的「别的方式」。

它不是 fulfilled 的词。
不是 3 扩 4，也不是焊进 fulfilled / not_fulfilled / not_evaluable。
它不是 not_fulfilled 的原因说明项，现在也不进原因栏。
它不是同一轮 Judge 再写一个结果标签。

若出现在人正在看的评估结果上，挂在同一条期望、「办成了没有」旁边。
挂在同一行，是因为对象仍是那一件，不得切粗切细。

人看见的那一格字，安放上可以说是一个结果标签；
这不是这块东西的名字，也不是选了「新增一个 judge 结果的标签」。

谁写下的：读已经裁完的前缀，不是同一张嘴再判。
现在这一格还不存在。
```

| 点名口 | 能不能当宿主 | 绝对原因 |
|---|---|---|
| 只是没办成的原因说明项 | 不能 | 改掉单位、三态出口、办成了×没立住、对象粒度 |
| fulfilled 从 3 态扩到 4 态 | 不能 | 第四个词仍是「这一次办成了没有」那张嘴；一个词写不下两套单位 |
| 放到说不清里面 | 不能 | 两种说不清不是同一个出口；职责内能力缺失不能自动变成这一次说不准 |
| 同一轮 Judge 再写一个结果标签 | 不能 | 刚写完办成了，下一句几乎一定对齐成也立住了；产品事实不再是前缀 |
| 别的方式：自己的看见格 | 这就是方案 | 对象仍是那一件，所以跟同一条期望走 |

人现在只能看见 fulfilled，是因为这一格还没开。不是因为它属于这三个词里的某一个，也不是因为它只属于没办成的原因。
