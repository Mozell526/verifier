# Discovery — 上一轮边界为什么还是会漂

用户本轮原话：

1. 你这个还是没把边界约束分清楚。
2. 「今天就办不了吗」本身有歧义和语境偏差。
3. 是 / 不是 在该歧义下都有可能引导向另外一个结果。
4. /council 重新分析：思考正确抽象，把边界都弄清楚，并且没有任何可能的歧义。

## 上一轮锁对了什么（本轮不重开对错）

- 029：那句题面必然换语境翻面。不是措辞不顺。
- 022：第二问必须是产品事实；承认 / 尽力 / 位置 不能当主问。
- 014：尚未支持 套到格式外或职责外必须失败。
- 死路仍死：第四态、尽力了=F、用说不清装定位内缺口、拿系统自报当标签。

## 上一轮没锁住的

030 把对象收成：

```text
正格 = (a) 这种事落在产品定位内
     + (b) 当前产品没有完成它的办法
```

这句定义里，「当前 / 完成 / 办法」仍然既能读成「这一次交付」，又能读成「产品里现成的那一档」。
029 杀掉的是口号，没有杀掉口号底下那套单位。所以用户说「边界约束还是没分清楚」成立。

同时，已锁 Consensus 对「第二问管多大一块」有三套话：

| 来源 | 第二问管多大 |
|---|---|
| 015 | 与三态正交；是产品承认处置 |
| 023 | 只在职责内之后，区分两种没办成 |
| 030 | 正交；办成了也不能自动排除正格 |
| 022 | 承认不能当主问 |

015 的「承认」和 022 打架。023 的「两种失败」和 030 的「办成了仍可正格」打架。
这不是命名问题，是边界本身还在晃。

## 本轮要锁的切法（待 architect 挑战）

两问同级，差在单位，不差在语气。

```text
第一问（fulfilled.md 已有）
  只看一件事：这一次，用户要的结果有没有给到
  单位：这一次请求 × 这一次交付
  不看：产品里现成有没有那一档
  不区分：没给到的原因（§2.2 已写）

第二问（出口还没有）
  只看一件事：用户要的这种事，产品里现成有没有做成它的那一档
  单位：这种事 × 产品里现成的那一档
  不看：这一次给没给到
  不区分：这一次尽没尽力、承不承认
```

认「这种事」是哪一类：只准看这一次请求。
答「现成有没有那一档」：不准看这一次交付。

职责内仍是隐藏前提，和第一问的「办成了」一样，不单独对外问「该不该管」。

## 碰撞只作形态

| 例子 | 第一问 | 第二问 |
|---|---|---|
| 漏了姓名 | 没办成 | 现成有（按姓名搜这一档在） |
| 投保年缺口 | 没办成 | 现成没有（形态例；去年是否职责内仍停） |
| 格式外编号 | 说不清 | 说不清（差在：对象未成形） |
| 查天气 | 说不清 | 说不清（差在：职责外） |
| 现成没有，但这回绕过给到了 | 办成了 | 现成没有 |
| 现成有，而且这回用上了 | 办成了 | 现成有 |

023 的 2×2 是两问交叉之后的对照表，不是第二问自己的定义。
015 的「承认」是第三问，022 已杀。
