# Discovery — 「今天就办不了吗」为什么会漂

用户本轮原话：

1. 上一轮还是没把边界约束分清楚。
2. 「今天就办不了吗」本身有歧义和语境偏差。
3. 是 / 不是 在该歧义下都有可能导向另一个结果。
4. /council 重新分析：思考正确抽象，把边界都弄清楚，并且没有任何歧义。

## 上一轮锁了什么（本轮不重开）

022：第二问必须是一件产品事实；承认 / 尽力 / 位置 不能当主问。
023：只松开 §2.2 一处压缩；漏做仍是第一问；「该做」保持隐藏中间量；2×2 不是对外词表。
024：「办得了吗」家族对、题面错；角色不得宣布采用那五个字。

死路仍死：第四态、尽力了=F、用说不清装定位内缺口、拿系统自报当标签。

## 上一轮候选为什么过不了本轮

甲/乙的题面是「今天就办不了吗」，词表是「是 / 不是 / 说不清」。

三个独立滑点叠在一起：

| 滑点 | 一种读法 | 另一种读法 |
|---|---|---|
| 「今天」 | 这一次会话 | 当前这个产品 |
| 「办不了」 | 这回没办成 | 产品没有这件事 |
| 「是 / 不是」 | 对含混谓语点头 | 对含混谓语摇头 |

评测员若带着会话语境听「今天就办不了吗」：

- 漏了姓名 → 是（这回没办成）
- 投保年缺口 → 是
- 查天气 → 是

三案一词，三关全破。

评测员若带着产品语境听同一句：

- 漏了姓名 → 不是
- 投保年缺口 → 是
- 查天气 → 仍可能是（产品也办不了天气）

正格仍可能吞掉职责外。所以不是「定义写清楚就行」——题面自己在请人读成另一问。

## 协议里其实已经有不可两读的那一格

`authority.md` §8.3 具名：

- 职责外
- 职责内能力缺失（应具备但未实现/表达不了）
- 职责内正常

`fulfilled.md` §2.2 把「功能本身未实现，但用户期望已提出」压进没办成，不区分原因。
013：这三类 statement 是挑 F/NF/NE 的隐藏中间量，挑完就吃掉。
015：若有第二问，只能与三态正交，标出定位内当前明确尚未支持的那一格，不回写 status。

上一轮错在把这一格翻译成口语「办不了」。
「办不了」比「职责内能力缺失」大：它同时盖住漏做、职责外、对象不成立。
对一个更大的谓语做是/不是，收不回那一格。

## 本轮要钉的

1. 题面不得与第一问同动词、不得让「今天」读成「这一次」。
2. 词表不得是是否；正格必须具名，补集只能写成「不得叫正名」并列出封闭排除。
3. 无歧义 = 换语境不翻面 + 失败对象不同格 + 不能靠第一问答完。不是再找一句更顺口的话。
4. 对外终句、要不要看见、改不改表，仍交给用户。
