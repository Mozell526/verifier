# Discovery — 第二问要抬到 fulfilled.md 同级

用户原话要点：

1. 「尽力了」可以看，但不确信是最好抽象，要看其他角度。
2. 「在这个产品该做的范围内，系统有没有正确承认：这一点我们现在还不支持？」太窄，没有泛化感；要换说法。
3. 抽象层级尽量类似 fulfilled.md。
4. 用户试探：「这件事，这个产品现在办得了吗？」
   - a) 类似 fulfilled：有没有做到用户需求
   - b) 类似我们能不能做；能不能做又分两种：
     1. 产品应该得能做但是没做到
     2. 当前受限于一些因素就是做不到（描述未切准）
   - 这两种可能和 fulfilled 混在一起
5. 「系统把用户这件事，放对地方了吗？」「按今天的产品定位，这次处置站不站得住？」——看着不合适，不懂位置是啥意思。

fulfilled.md 的「层级」不是文风，是这几条结构：

- 从业务角度，不是实现角度
- 只看一件事
- 封闭三态，不新增第四态
- 没办成不区分原因
- 期望从用户视角写
- 材料够不够是回答第一层的前提，不是另一个对错

所以第二问如果存在，必须也是「一件事 + 封闭词表 + 业务事实」，不能是评测员对态度/位置/披露的打分。

013–015 已锁：不能第四态、不能尽力了=F、不能用 NE 表达定位内缺口、不能拿系统自报当标签。本轮不重开这些死路，只重开「那一句问法」。
