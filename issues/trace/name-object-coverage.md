# 原则 — 对象覆盖（不是句子形态，也不是题型）

本轮只定原则 / 标准 / 边界。不发版。不改判定代码。

上一轮「整句被收成一个身份」已被用户否掉气质：它只在「用户只打了一个词、系统只交一个字段、这个字段还长得像姓名或单号」时出手。大多数题它根本没动。那不是泛化，是局部地板。本文件把它降成第 7 节的特例，不再当架构卖。

覆盖所有情况，靠的不是穷举题型，而是每个输入都有定义结果。

---

## 1. 我们在评什么

只评一件事：用户要的事，系统办成了没有。

- 问句 = 用户要什么
- live 交出来的条件 = 系统实际做了什么
- 不能从问句发明成功。问句里写了「李明」，live 没交姓名，就不能判成功。

这是 `spec/alg/fulfilled.md` 第一章的尺子，不是画布上的句子，也不是 341 条对错率。

---

## 2. 看什么 / 不看什么

### 看

1. 用户问句的原文
2. live 交出的每一条条件：字段名 + 值
3. 字段名告诉我们这是哪一种对象（姓名 / 单号 / 产品或地址 / 其他）
4. 1A 已经拍过的姓氏目录，只用来认「这个姓名对象能不能单独撑成功」
5. live 已经交过的产品名 / 地址，只用来挡住「金凤这种目录词被当成姓名出口」

### 不看

1. 混合包上的场景角色（true_bare_name / name_plus_policy / …）
2. 问句像不像「人名+保单」「人名+产品」——不问句定题型
3. 不剥「的 / 查一下 / 帮我找 / 保单号」——剥了就是下一张规则表
4. 不点名某条 341 ID 当规则
5. 不代选昊轩 / 去年 / 称谓 / 格式外

## 3. 词表（禁止两读）

| 词 | 只准读成 | 不准读成 |
|---|---|---|
| 对象 | live 交出的一条条件（字段类型 + 值） | 问句里猜出来的题型 |
| 跨度 | 值在问句里的一段连续原文 | 「意思沾边」 |
| 残句 | 去掉所有已交付跨度之后，问句里还剩的字 | 人工认为不重要的字 |
| 残句为空 | 剩下的字去掉首尾空白之后什么都没有 | 剩下的都是虚词 / 标点 / 业务词，所以当没有 |
| 主动改判 | 本原则自己给出成功或失败 | 沿用当前判定的结果 |
| 不改判 | 本原则不出手，沿用当前判定 | 已经识别出假姓名 / 已经判失败 |
| 身份对象 | 字段是姓名或客户号 / 保单号 | 任何看起来像人的词 |

三态对本原则的封闭定义：

| 态 | 含义 |
|---|---|
| 主动改成功 | 本原则有把握：用户要的身份对象已经按原文交齐 |
| 主动改失败 | 本原则本轮**不使用**。主动改失败就是在声称「我认出这是假的 / 这不该成功」 |
| 不改判 | 证据不够、或超出本原则授权。当前是失败就还是失败，当前是成功就还是成功 |

不改判不是漏洞。它是「所有还没被原则覆盖的情况」的正式去处。

## 4. 标准（全函数，没有「看情况」）

任意一对 (问句, live 条件列表)，按下面顺序走，必须停在其中一格。

### 4.1 先检查能不能对齐原文

1. 问句去掉首尾空白后是空的 → **不改判**
2. live 一条条件都没有 → **不改判**（不能从问句补对象）
3. 字段和值对不齐（一条条件里值是一串列表、展平后对不上）→ **不改判**
4. 某个值是空的 → **不改判**
5. 某个值不是问句里的连续片段 → **不改判**
6. 两段跨度抢同一段原文 → **不改判**

对齐方式锁死，禁止两读：按 live 条件出现的顺序，在问句里取第一段尚未占用的相同连续原文。任一值占不到这样一段 → 不改判。禁止换一种对齐（从右往左、最短优先、人工挑一段）把同一输入改成主动改成功。

### 4.2 再看残句

7. 把所有跨度从问句里挖掉，剩下的字去掉首尾空白后**不是空的** → **不改判**

这一条是边界，不是实现细节。  
「红莲保单」交了「红莲」，剩下「保单」→ 不改判。  
「张忠波保单号」交了「张忠波」，剩下「保单号」→ 不改判。  
「查一下李明」交了「李明」，剩下「查一下」→ 不改判。  
「李明的重疾险」交了「李明」和「重疾险」，剩下「的」→ 不改判。

不猜「保单号」是不是次要词。猜了就是规则表。

残句比较前去掉的空白 = Unicode whitespace（含全角空格），不是虚词。空格、换行、制表、全角空格可以忽略。逗号、问号、「的」、「查一下」、「保单号」都不能忽略。

### 4.3 残句为空，还要看对象类型

残句为空只说明：live 交出来的值，把问句原文盖住了。  
**这还不够判成功。** 真实反例：问句「综拓潜客」，live 交了「综拓」+「潜客」，残句为空，当前是失败。如果残句为空就改成功，这口会把分群词抬飞。

所以残句为空之后：

8. 交出来的对象里，**一个身份对象都没有**（没有姓名，也没有客户号 / 保单号）→ **不改判**  
   本原则只授权关闭「带着身份对象的请求」。纯产品、纯地址、纯分群，交给别的判定，不在这里冒充成功。
9. 有身份对象，但其中某一条姓名对象过不了 1A 门 → **不改判**  
   1A 门（合取，不是题型）：2–4 个汉字 + 姓氏目录命中 + 不是产品 / 地址目录词。  
   共展 / 豆芽 / 昊轩：残句可空，但无姓 → 不改判。**不准主动改失败。**
10. 对齐且残句空，但出现 `other` 字段（既不是姓名、单号，也不是产品 / 地址）→ **不改判**
11. 有身份对象，且每条姓名对象都过 1A 门，其他对象只是单号或产品 / 地址字段 → **主动改成功**

单号对象本身没有「像不像单号」的正则。字段名是客户号 / 保单号，值又盖住了原文，就够了。

## 5. 授权边界（这口可以动什么）

| 可以主动改成功 | 不可以主动改 |
|---|---|
| 整句真名，live 交了这个姓名 | 共展 / 豆芽（不改判，保持失败） |
| 整句单号，live 交了这个单号 | 金凤只作为产品出现（不改判，不走姓名出口） |
| 将来 parser 交出「李明」+「重疾险」，问句恰好是「李明重疾险」 | 「李明的重疾险」——还有「的」 |
| 将来 parser 交出两个单号，问句恰好是这两个号连在一起 | 「找一下客户号C000…」——还有「找一下客户号」 |
| | live 空的「家办客户」 |
| | 「红莲保单」只交了「红莲」 |
| | 「张忠波保单号」——不改判，所以不会误杀当前的成功 |
| | 盘客、去年、称谓、昊轩 |

主动改失败：本轮空集。  
原因：一旦允许主动改失败，就会重新长出「保单号否决」「假姓名黑名单」「问句里有产品就否决」这些规则。假姓名闸继续由集 A 的当前失败守，不由这口假装「已经会认假」。

## 6. 每个输入都有定义结果

把输入空间拆开。每一格只有一个结果。

| 问句 | live | 跨度 | 残句 | 对象 | 结果 |
|---|---|---|---|---|---|
| 空 | 任意 | — | — | — | 不改判 |
| 非空 | 空 | — | — | — | 不改判 |
| 非空 | 有 | 对不齐 / 对不上原文 / 重叠 | — | — | 不改判 |
| 非空 | 有 | 对齐 | 非空 | 任意 | 不改判 |
| 非空 | 有 | 对齐 | 空 | 没有姓名也没有单号 | 不改判 |
| 非空 | 有 | 对齐 | 空 | 有姓名，但姓名不过 1A 门 | 不改判 |
| 非空 | 有 | 对齐 | 空 | 出现 other 字段 | 不改判 |
| 非空 | 有 | 对齐 | 空 | 有姓名或单号，姓名若出现则过 1A 门，且没有 other | 主动改成功 |

没有第 9 格。没有「视题型而定」。

## 7. 和上一轮整句覆盖门的关系（必须写明，避免再发明）

上一轮的 `exit_live_identity` 是本原则的一个特例：

> 恰好一条 live 条件，并且这条的值等于整句问句。

在这个窄条件下，残句必然为空，第 4.3 节退化为「按那一个字段的类型出口」。  
所以：整句相等不是新原则，只是对象覆盖在单字段、值=问句时的投影。

本原则多出来的、真正不同于整句相等的点只有：

- 允许多个对象一起把问句盖住（例如「李明」+「重疾险」盖住「李明重疾险」）
- 明确残句非空必须不改判（所以「红莲保单」不会因为长得像人名+保单而被抬成功）
- 明确没有身份对象时，即使残句为空也不改判（所以「综拓潜客」不会被抬成功）
- 明确不主动改失败

如果冻结痕迹上几乎没有「多对象且残句为空」的身份题，本轮分数可以和整句覆盖门完全一样。那不是失败。那说明冻结数据还刷不出第 7 节之外的新分；赢的是「何时不许出手」，不是表上的数。

## 8. 反例（用来证伪，不是用来当规则）

这些句子不是规则条目。哪一口踩了，哪一口就不是本原则。

1. 把「红莲保单」抬成功 —— 残句非空还出手了
2. 把「张忠波保单号」改成失败 —— 残句非空却主动改失败
3. 把「家办客户」抬成功 —— live 是空的，从问句发明了成功
4. 把「李明的重疾险」在 live 没交姓名时抬成功 —— 从问句补了人
5. 把「共展」主动改失败并写成「已经会认假姓名」—— 把不改判假扮成检测
6. 把「综拓潜客」抬成功 —— 残句为空但没有身份对象
7. 为了让「查一下李明」也成功，开始剥「查一下」—— 下一张规则表
8. 用混合包角色决定出哪条路 —— 问句定题型

---

## 9. 没覆盖的，正式停在不改判

- 昊轩：二字无姓。1A 没拍。不改判。
- 去年 / 称谓 / 格式外：不改判。
- 姓名+产品而 parser 把姓名丢掉：不改判，保持失败。这是解析问题，不是判定问题。
- 用户打了一整句人话，系统只交了其中一部分：残句非空，不改判。

「能覆盖所有可能出现的情况」= 上面这些都有去处，不是 = 全部改判对。
