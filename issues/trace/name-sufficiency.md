# 原则：字段标准 + 充分性，不是覆盖门

本文件是 042–045 的原则正文。打完就扔的针在文末。
不要把针表抄进定义。

## 1. 我们在评什么

只评一件事：用户要的事，系统办成了没有。

- 问句 = 用户要什么
- 系统交出来的条件 = 系统实际做了什么
- 不能从问句发明成功

1A 不是「这是姓名题所以怎样」。
1A 只回答：交出来的这个姓名值，够不够撑住**姓名这一维**。

「整句办成了没有」是另一问。两问不得焊成一个字符串几何门。

## 2. 看什么 / 不看什么

看：

1. 用户问句
2. live 交出来的字段和值
3. 该字段已经拍过的证据标准（姓名维 = 1A）

不看：

1. 混合包 `role` / 题型名
2. 问句是不是「姓名题」
3. 挖掉交付值之后残句空不空
4. 虚词表（的 / 一下 / 查一下 / 岁 / 以上）
5. 系统自报、`is_supported`、canvas、341 准确率

## 3. 两问必须拆开

```text
Q1  字段证据标准
    这个交出来的值，够不够撑住它自己那一维？
    姓名维：2–4 个汉字、有姓、不是本产品/地址目录里的词
    单号维：值就是交出来的客户号或保单号
    别的维：本轮不授权这张嘴说话

Q2  充分性（能不能改整句）
    我们有没有「足够」的证据，证明用户要的事就是这一维、
    并且这一维已经按 Q1 交齐？
    充分 ≠ 必要。
    本轮唯一授权的充分性测试：
        恰好一个字段，值等于整句，且该字段通过 Q1
```

Q2 不是「残句为空」。
残句为空是在定义「问句被消耗完了」。那是句子形状，不是「用户要的事办成了没有」。

## 4. 封闭出口（全函数）

任意一次「问句 × live 条件」只落两态：

| 态 | 何时 | 意思 |
|---|---|---|
| 主动改成功 | Q2 的充分性测试打中，且 Q1 通过 | 这口有把握：用户要的就是这一维，并且交齐了 |
| 不改判 | 其他所有情况 | 证据不够，或超出这口的授权。当前失败还失败，当前成功还成功 |

禁止第三态「主动改失败」。
一改失败，就是在声称「我认出这是假的」。本轮没有这张授权。

不改判不是漏洞。它是所有还没被授权说话的情况的正式去处。
「能覆盖所有可能出现的情况」= 每一格都有去处，不是 = 全部改判对。

## 5. 1A 的位置

1A 只进 Q1 的姓名维。

- 杨杰、王坤林：值是 2–4 字、有姓、不是目录产品/地址 → 姓名维过
- 共展、豆芽：残句空也过不了姓氏门 → 不改判，保持失败
- 昊轩：二字无姓，停住 → 不改判
- 金凤当姓名交：在产品目录里 → 姓名维不过

1A 不得回答 Q2。
「交了一个过 1A 的姓名」≠「用户要的事办成了」。

## 6. 为什么覆盖门是规则化

对象覆盖问三件事：值是不是原文、挖掉后还剩字吗、有没有姓名或单号。

这三件事对任意输入都问，所以看起来没有题型名。
但它把 Q2 定义成了「残句为空 + 必须有身份字段」。

扩散失败的形状：

1. 「唐诗颖的生存金有没有领取」交了姓名=唐诗颖。残句不是空的。
   若把 1A 当成整句成功，会把生存金题抬成办成了。
2. 「红莲保单」交了姓名=红莲。残句是「保单」。
   覆盖门靠残句挡住；字段门会误抬。
3. 「李明的重疾险」交齐姓名+产品后还剩「的」。
   要抬它，就得剥「的」。剥虚词就是下一张规则表。
4. 「45岁女性保费10万以上」交齐年龄/性别/保费后还剩「岁/以上」。
   覆盖门因为没有姓名/单号而闭嘴；要让它张嘴，就得再加字段类，再剥「以上」。

所以：覆盖门不是原则。它是身份句上的句子消耗规则。
整句相等只是它在「恰好一个字段且值=问句」时的投影。两者都不是 Q2 的定义。

本轮唯一合法关系：

```text
整句相等 + 字段标准
  = 本轮授权的充分性测试
  ≠ 「用户要的事办成了没有」的一般定义
  ≠ 覆盖门的特例（不允许再把覆盖门扶正，再把整句相等降成它的特例）
```

## 7. 和规则表差在哪

被否掉的形状：先看这是哪种题，再查表。新句子来了就再加一行。

覆盖门换了一种形状：先看残句空不空，再看有没有姓名/单号。
新句子来了，就要再剥虚词、再加字段类。

本轮的形状：只在充分性打中时说话。新句子来了，打不中就停在不改判。
不新开「某某题型」，不新开「某某虚词」。

## 8. 碰撞针（打完就扔，不写进定义）

| 用户说的 | 系统交出来的 | 这口怎么走 | 为什么 |
|---|---|---|---|
| 杨杰 | 姓名=杨杰 | 主动改成功 | 值=整句，1A 过 |
| 王坤林 | 姓名=王坤林 | 主动改成功 | 和杨杰同侧 |
| 共展 | 姓名=共展 | 不改判，保持失败 | 不过 1A 姓氏门。不是「已经会认假姓名」 |
| 昊轩 | 姓名=昊轩 | 不改判 | 停住，不代选 |
| 红莲保单 | 姓名=红莲 | 不改判，保持失败 | 充分性没打中。字段门会误抬，所以字段门不是候选 |
| 唐诗颖的生存金有没有领取 | 姓名=唐诗颖 | 不改判，保持失败 | 用户还要了生存金。字段门会误抬，这就是扩散失败 |
| 张忠波保单号 | 姓名=张忠波 | 不改判，保持当前成功 | 充分性没打中，所以不会误杀 |
| 李明的重疾险 | 姓名=李明，产品=重疾险 | 不改判 | 剩「的」。剥「的」就是下一张表 |
| 李明重疾险 | 姓名=李明，产品=重疾险 | 不改判 | 充分性没打中。本轮不授权覆盖门去抬它 |
| 李明的重疾险 | 只交了产品 | 不改判，保持失败 | 判定不许补人。这是解析问题 |
| 家办客户 | 什么都没交 | 不改判，保持失败 | 不能从问句发明成功 |
| 45岁女性保费10万以上 | 年龄+性别+保费 | 不改判 | 本轮没授权这些维。覆盖门要张嘴就得加规则 |
| 有生存金未领取 | 某个生存金字段 | 不改判 | 同上 |

这些针若被写进原则正文当类型行，本文被越权。

## 9. 可证伪

1. 只看这一次交了姓名，就标整句成功 → 原则失败。
2. 必须先把问句分进预置类型才能答 → 原则失败。
3. 靠残句为空 / 剥虚词才能多抬一条 → 原则失败。
4. 未在针里出现过的新形状，必须加行才能落格 → 原则失败。
5. 主动改失败 → 原则失败。
6. 冻结集上 `field_only` 没有误抬「姓名已交、用户还要了别的事」→ 本轮消融失败。
7. 后文再把对象覆盖写成充分性原则的上位 → 本轮失败。
