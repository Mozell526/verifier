# 判定代理在评什么（内存，T4）

本文件是内存实验的原则正文。不是发版口径，也不改正式文件。

## 1. 我们在评什么

只评一件事：用户要的事，这次办成了没有。

- 问句 = 用户要什么
- 系统交出来的条件 = 系统实际做了什么
- 该维已经有的标准 = 只读尺子，判定代理不另造尺子

单位永远是：这一次请求 × 这一次交付。
不要先给问句贴类型，不要按题型换嘴。

## 2. 两问永远拆开，对任何输入同一套

```text
Q1  已有字段标准
    对这次交出来的每一个字段：
    若该字段已经有标准，消费那条只读检查。
    若该字段本轮没有已有标准，不要发明标准，
    也不要因为没有标准就判这一字段失败。
    这一问看值，不看用户怎么措辞。

Q2  整句有没有被说清
    把这次交出来的全部条件合在一起，
    看用户要的事有没有被说完。
    不是对字符串，不是数汉字，不是剥残句。
    不是“值等于整句”。那只是一种够用的情况。
```

## 3. 封闭出口（穷尽，无第三套题型嘴）

```text
交付读不到                     → unclear
交付读得到：
  整句没被这次交付说清         → not_fulfilled
  整句已被这次交付说清：
    存在已有标准且有一条撑不住 → not_fulfilled
    所有已有标准都撑住
    或本轮没有任何已有标准     → fulfilled
```

“说不清 / unclear”只用于读不到交付。
不要用它逃避 Q1 / Q2 已经能开口的情况。

没有“inherit”这张判定代理的嘴。
inherit 是字段充分性旁路“这一维先不说话”，不是判定代理自己。

## 4. 看什么 / 不看什么

看：

1. 用户问句
2. 系统交出来的全部字段和值
3. 这些字段已经有的标准

不看：

1. 题型名、混合包角色、样本编号
2. 问句是不是“姓名题 / 单号题 / 产品题”
3. 挖掉交付值之后残句空不空
4. 虚词表
5. 为某个样本加的例外
6. 交出来的字段个数本身（个数不是对错）

## 5. 边界例子（说明原则，不是类型表）

同一套两问，不按题型换规则：

- 只说「杨杰 / 张伟 / 王坤林」，也只交了这个姓名，姓名尺撑住 → 办成了
- 只说「共展 / 豆芽」，也只交了这个姓名，姓名尺撑不住 → 没办成
- 「红莲保单」只交了姓名；「唐诗颖的生存金」只交了姓名；
  「李明的重疾险」只交了产品；「张忠波保单号」只交了姓名
  → 整句还要了别的，没办成
- 「李明的重疾险」姓名和产品都交了，已有标准没有撑不住的 → 办成了
- 只说客户号 / 保单号，也只交了这个号，号非空 → 办成了
- 同一句「金凤」：交成姓名且姓名尺撑不住 → 没办成；
  交成产品且没有撑不住的已有标准 → 办成了
  （判定代理不先宣布这是姓名题还是产品题）

## 6. 和对照几何的关系

“恰好一个字段、值等于整句、该字段有授权标准”是 Q2 的一种够用情况。
它不是定义，也不是判定代理本身。
程序化对照只用来揭穿“换皮规则化”，不能拿它当发版嘴。


## 7. T4 只收紧第二问的测量方向（候选，尚未发版）

T3 的两问和出口不变。T4 只补第二问缺的边界：

- 用户要的事 = 原始问句。摘要 / 改写 / 意图标签不是问句。
- 交付对着问句量，不许把问句收到已有交付那么小。
- 问句里还要了、这次却没有对应条件的，就是没说清。
- “没有具体值”不能把那一部分收成语气或修饰。
- “查一下 / 帮我找”是说法，不是另一件事。

这不是题型表。不先宣布姓名题 / 单号题 / 产品题。
不列“对象 / 凭证 / 产品 / 状态”去分流。
昊轩 / 去年 / 称谓 / 格式外 / 对外中文：仍停住，不代选。

## 8. T4b 测量方向（内存对照，不是发版）

T4 已经钉住：原始问句为准，不许把问句收到交付那么小。
T4 正文里还留了两个说法例子（「查一下 / 帮我找」），以及「不要收成语气或修饰」。
用户担心的正是：看起来是原则，承重的其实是这两个例子。

T4b 不换两问，只把第二问的测量收成一件可对任意输入问的事：

```text
判断问句某一部分要不要对应条件，只问：
拿掉这一部分，这次办成的标准会不会变。
会变 → 指定了找什么或按什么收窄，必须有对应条件
不变 → 只是在提出请求，不是另一件要办的事
```

这一节不是类型表，也不列说法词。
T4 冻结 12 条仍以 §7 / PRINCIPLE_T4 为准。
T4b 只回答：拿掉例词之后，同一张嘴还能否在正常句、假姓名、混合句上立住。

## 9. T4d 测量方向（内存对照，不是发版）

T4 / T4b / T4c 的两问和出口不变。T4d 只补两问之间的边界：

```text
两问互相独立，谁也不能替谁回答。不要发明第三问。

Q1  必须按字段消费已有标准。
    「值跟问句写的一样」不是标准。
    第二问看起来已经说完，不能用来跳过第一问。

Q2  对着原始问句看：点到的内容有没有对应交付。
    点到 = 问句里出现了这次要据此查找或交出来的内容。
    没点到 = 问句只是在发出这次请求。
    有没有写出可检索的具体值，不改变有没有点到。
    不能因为没有写出具体值，就把已经点到的内容改口成不用交。
    第一问过了，不能用来证明第二问过了。
```

这一节不列说法词，不列「保单 / 保单号」，不按题型换规则。
T4 冻结 12 条仍以 §7 为准。T4d 只回答：Q1 和 Q2 拆开之后，
假姓名加说法、以及点到了却没有具体值的内容，会不会同时立住。

T4d 跑完（内存，不是发版）：同一套 13 针 13 / 0；3 条未见过的观察针（劳驾查下杨杰 / 劳驾查下共展 / 张伟保单信息）按同一套两问落地。冻结 12 条仍以 §7 为准。

## 10. T4e 测量方向（内存对照，不是发版）

用户已锁：I007「张忠波保单号」只交姓名，正式算办成。
T4d「点到了即使没有具体值也还要交」会把 I007 打成 NF，和正式口径冲突。
T4e 不换两问，只把第二问从「句里点到的名词」收成「这次实际给出的查找依据」。

```text
两问互相独立，谁也不能替谁回答。不要发明第三问。

Q1  必须按字段消费已有标准。
    「值跟问句写的一样」不是标准。
    不要因为问句短、或问句只是一个词，就另设门槛。
    第二问看起来已经说完，不能用来跳过第一问。

Q2  对着原始问句看：这次实际给出的、能够用来查找或筛选的依据，是否都有对应交付。
    能够用来查找或筛选的依据 = 问句里给出的、可以拿去找人或收窄集合的内容。
    只是在发出这次请求的部分，不是另一件要办的事。
    只点了某个字段的名字、没有给出可用来查找的值，不是另一件必须交出来的条件；也不许为此虚构一个值。
    已经给出了可用来查找或筛选的值，却没有对应交付，就是没说清。
    第一问过了，不能用来证明第二问过了。
    办成标准 ≠ 检索结果集会不会变。
```

这一节不列说法词，不列「保单 / 保单号」，不按题型换规则。
