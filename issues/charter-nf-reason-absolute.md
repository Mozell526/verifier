# Charter — 这块东西是不是 not_fulfilled 的原因说明项

> 用户本轮钉死两句：
> 1. 认得的只有贴出来的这一块，不是「第二问」。
> 2. 仍然觉得它像 not_fulfilled 的原因说明项；若方案不这样定，必须给出排除它的绝对理由。
> 同时要给安放方案，并给出排除其它点名口的绝对原因。不实现。

上一轮 `charter-recognized-exit.md` / 089–092 已有方案句。本轮不是重贴那句，而是把「像原因说明项」这条疑惑按绝对标准重审。090 的「只补 NF 会弄丢一格」若站不住，本轮必须改口，不得靠「第二问」硬撑。

## 1. Goal & Definition of Done

- Goal: 钉死这块东西的安放。主语是用户贴出的那一块。必须先回答：它是不是 not_fulfilled 的原因说明项；若不是，排除必须是绝对的，不是口味。
- Done:
  1. 每个根因一个 issue + 现行出口原文 + 已锁 Consensus；
  2. architect 独立重读协议、现行原因栏、authority §8.3 后写 Consensus；
  3. 交给用户的是一句方案：这块东西的出口放在哪；以及排除「原因说明项 / 3 扩 4 / NE / Judge 再写标签」的绝对原因。

「绝对」在本轮的工作定义（可证伪）：

1. 排除某口，必须指出：把这块东西放进那口，会改掉用户已锁的对象、单位、不看什么、或三态出口里至少一项；
2. 不得用「更干净」「更好读」「第二问同级」代替；
3. 若某口并不改掉已锁内容，不得排除，必须改方案去就那口；
4. 「只在没办成时才给人看」是看见时机，不是身份。看见时机仍停在 §4，不得拿它冒充安放。

「方案」在本轮的工作定义：

1. 能用一句话说清出口放在哪一层、哪一格；
2. 主语必须是这块东西本身，不得先改名为「第二问」再推安放；
3. 必须同时说清：是不是 NF 的原因说明项，是不是 fulfilled 的第四个词，是不是 NE，是不是 Judge 再写一个结果标签；
4. 不得只交一份「四个口都不能」而不给方案句。

## 2. Oracle

- **对错尺子**：用户本轮贴出的那一块；`spec/alg/fulfilled.md` 第一章；`spec/alg/authority.md` §8.3；现行原因栏（`impl/core/summary.py` `summary_from_fulfillment`、`impl/core/frontend_view.py` `display_reason`、`impl/frontend/summary.html` 评估卡「原因」）；040 Consensus 里关于单位 / 出口 / 「办成了不能自动排除没立住」的内容；047 Consensus 里关于同一张嘴兼答的内容。
- **不是 oracle**：「第二问」这个名字、canvas、准确率、`is_supported=false`、空条件、「暂不支持」文案、姓名/年/天气类型表、089–092 的方案名（本轮可打其是否仍被「原因说明项」打穿）。

已锁、本轮不得重开内容：

```text
只看一件事：用户要的这件事，产品把它立成自己会做的事了没有
对象：仍是 fulfilled 那一件
      不得另立类型表
      不得为了更好答这一块，把对象切粗或切细
单位：这件事 × 产品事实
产品事实从哪来：已经裁完的能力/职责判断，及其依据资料
          不是这一次给没给到
          不是库存字段表
          不是「先分成姓名/年/天气」
不看：这一次交付；这一次承不承认 / 尽没尽力；预置类型表
不区分：没立住的技术原因
出口：立住了 / 没立住 / 说不清
```

「立住了 / 没立住 / 说不清」继续只是内部手柄，不宣布采用为对外题面。
fulfilled 继续只评：这一次，用户要的事办成了没有。不并进，不新增第四态。

本轮可以改口的：

- 089–092 若把「原因说明项」排除得不够绝对，必须重写排除句或改方案；
- 把这块东西叫做「第二问 / 兄妹问」再推出安放。
