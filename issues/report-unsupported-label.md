# Report — 第二问该和 fulfilled 同级，不该收成「承认尚未支持」

用户反馈：

1. 「尽力了」能懂，但不确定是最好的抽象，要看别的角度。
2. 「在这个产品该做的范围内，系统有没有正确承认：这一点我们现在还不支持」太窄，不像 fulfilled 那种层级。
3. 「这件事，这个产品现在办得了吗」接近想要的高度；能不能做似乎又分成「该能做却没做到」和「当前就是做不到」，担心和 fulfilled 搅在一起。
4. 「放对地方 / 处置站不站得住」不合适，位置是什么听不懂。

本轮不改协议、不改字段、不重判 case。只把第二问抬回和 fulfilled 同一层。

## 已经钉死的（不动）

- 不能给「办成了」加第四个值
- 不能把「尽力了」算成办成了
- 不能用「说不清」表达「今天就是办不了」
- 不能拿系统自报的「不支持」当官方标签
- 去年 / 称谓 / 格式外仍停住，先不定功能地图

## 和 fulfilled 同级的问法

`fulfilled.md` 自己就是这一层：

```text
只看一件事——系统有没有帮用户办成想办的事。

判断分两层：
  第一层：用户要的事办成了没有？
  第二层：手里的材料够不够回答第一层？
```

它内部其实先问过「该不该、办不办得了」，再问「这次办成了没有」，对外只留下后一句。
上一轮把后一句旁边那层收成了「正确承认尚未支持」，那是其中一个格子，不是那一层本身。

同级候选只有三个角度：

| 角度 | 只看一件事 | 三个词 | 适合当什么 |
|---|---|---|---|
| A. 结果（已有） | 系统有没有帮用户办成想办的事 | 办成了 / 没办成 / 说不清 | 主问题，不动 |
| B. 能力（推荐） | 这件事，今天这个产品办得了吗 | 办得了 / 办不了 / 还说不清 | 和 A 并排的第二问 |
| C. 该管吗 | 这件事是不是这个产品该管的 | 该管 / 不该管 / 还说不清 | B 的上游，更窄 |
| D. 尽力了 | 能做的做完了、做不了的说清了吗 | 说清了 / 没说清 | 附注，不能当主问题 |

「放对地方」「处置站得住」丢掉。那不是 fulfilled 的层级，位置也没有业务含义。

## 和 fulfilled 怎么分开

用户说的两种「能不能做」，其实不是 B 的两个值，是 A × B 的两个格子：

```text
                    办成了            没办成                 说不清
办得了              正常交付          该能做，却没做到         材料不够
办不了              不该靠拒绝换办成  今天就是办不到           不应用「说不清」装长期办不了
还说不清办不办得了  —                 —                      依据不够，先别判能力
```

- 「产品应该能做但是没做到」= 办得了 × 没办成。这是结果问题，已经在 fulfilled 里。
- 「当前受限于一些因素就是做不到」= 办不了 × 没办成。这才是第二问要单独看见的。

所以 B 不会和 A 抢词，只要不把「该能做却没做到」写进「办不了」。

「办不了」以后若要写「差在哪儿」，用和 fulfilled「说不清差在哪儿」同一手法即可：今天产品就没有这一维 / 用户给的不是可办的对象 / 根本不该这个产品管。那是下一层，不是现在的主词。现在不必命名，更不必填功能地图。

## 你现在要定的

不要在「承认尚未支持」那句上答要不要。先定第二问的角度：

- **B**：和 fulfilled 成对。对外同时看见「办成了没有」和「今天办得了吗」。
- **C**：只看见「该不该这个产品管」。更干净，但看不见「该管、今天却办不了」。
- **D / 只要尽力了**：当附注可以，当主问题不行；会诱人把没办成改成办成了。
- **只要 A**：不增加第二问。本轮结束。

若选 B 或 C，再选两件小事：这段话写在哪；现在改不改评测结果的结构。
