# Charter — 第二问必须是原则，不能是类型表

> 本轮只辩抽象，不重开 006–038 的对错结论，不改代码，不改协议正文。
> 不覆盖已有章程。032–034 的五条结构条款默认仍活；本轮要审的是：
> 那套「认哪一类 / 那一档 / 四例对照」的写法，是不是又滑成规则化。
>
> 用户更新：思考正确抽象，把边界都弄清楚，不要有规则化。
> 排除所有可能的歧义，能覆盖所有可能出现的情况。

## 1. Goal & Definition of Done

- Goal: 钉死第二问在 `fulfilled.md` 同级的原则（看什么 / 不看什么 / 单位 / 封闭出口），并证明它是全函数，不是预置类型表。
- Done:
  1. 每个根因一个 issue + 协议原文 + 翻面/穷尽测试；
  2. architect 独立重读协议后写 Consensus；
  3. 交给用户的是无歧义、非规则化、能盖住任意新形状的原则；不是再找一句口语，不是上线字段，不是把例子扩成更长的表。

「不要有规则化」的工作定义（可证伪）：

1. 原则只许规定：看什么、不看什么、单位、封闭出口。对任意输入同一套。
2. 若必须先把「用户要的事」分进预置类型（姓名 / 投保年 / 格式外 / 天气 / …），再按类型查表，即为规则化。
3. 新形状若要靠「再加一行」才能落格，即为规则化。

「能覆盖所有可能出现的情况」的工作定义（可证伪）：

1. 覆盖 = 全函数：任意一次「用户要的事 × 产品事实」必落三态之一。
2. 覆盖 ≠ 把能想到的情况列完。例表只许当碰撞针，不许当定义。
3. 未在例表里出现过的形状，仍必须不改原则就能落格。

「排除所有可能的歧义」沿用并收紧：

1. 定义里的谓语，不能既可读成「这一次交付」，又可读成「产品把这件事立住了没有」。
2. 答第二问时，不得靠看这一次给没给到来得出答案。
3. 第二问不得另切一件更粗或更细的事。对象必须和第一问是同一件「用户要的事」。
4. 漏做 ≠ 份内没立住 ≠ 职责外 / 对象未成形。

## 2. Oracle

- **对错尺子**：`spec/alg/fulfilled.md` 第一章（只看一件事、三态、不区分没办成的原因、不新增第四态）、`spec/alg/authority.md` §1 / §8.2 / §8.3、`spec/alg/material-positioning.md` 不变量 1、`spec/info-volume.md`（不引入 partial、不需要第二套对错）、013–015 / 022–024 / 029–034 Consensus（死路仍死；032–034 五条结构条款默认仍活，除非本轮用协议原文证伪其「认哪一类 / 那一档」的操作化）。
- **不是 oracle**：canvas、准确率、`is_supported=false`、空条件、「暂不支持」文案、常识功能地图、对外口语、内部手柄用字。
- 漏姓名 / 投保年 / 格式外编号 / 查天气 只当碰撞针，不重判对错，不预填去年 / 称谓，也不得写成第二问的类型表。

## 4. Escalation

1. 要不要对外看见第二问
2. 用哪一句中文当对外题面
3. 现在改不改 schema
4. 去年算不算核心 / 称谓认不认 / 格式外算不算单号（仍停住）

本轮若原则已经锁住，看见与否只在报告里点一下「仍停住」，不要再把它写成用户必须先交的作业。

## 5. Evidence standards

- 协议原文 + 已锁 Consensus。不得用「我感觉更没有规则化」代替：单位对照、不看条款、全函数测试、换语境翻面测试。
- architect 必须自己重读 cited 协议，不抄 verifier 转述。
- 任一候选若依赖预置类型表，或新形状必须加行，或另切了第一问的对象，即未达本轮。
- 032–034 的五条若仍成立，不得整包推翻；只许改「认哪一类 / 那一档」这种操作化。
