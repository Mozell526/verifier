### Reasoning
「不要 fulfilled 这种业务词、要能标出产品定位以内尚未支持」这个需求成立。把它做成与办成了 / 没办成 / 说不清**平级**的新状态，不成立。协议已经给了功能未实现的位置：它是 NF 的一种理由（§2.2），或 NE 的「差在哪儿」（§2.3），或维上的 non-blocking 说明（L1522），不是第四个 overall。

不是过刚——对 **judge 出口和报表主列**。第四个整体词会变成 D3 的新逃逸口：态度好、没乱编 → 既不是没办成，也不是说不清。013 的探针立刻失效：I161 与 I034 进同一格；007 / 009 的出口作废；盘客/活动也会挤进来。老板那句「这次帮用户找到人了没有」将无法从主列读出。

对挑战「review-only 别名是否可接受」的收口：

- **可以**的，只有三态的展示改名（办成了 / 没办成 / 说不清，或不叫 fulfilled）。章程 §4.4 已经把「对外中文名、若只是展示名、不改三态」留给用户。那不是第四态。
- **不可以**的，是评审侧再开一个整体桶叫「尚未支持」。即便 judge JSON 仍只吐三态，只要报表/复核把 I161 和 I034 收进同一格，它就是第四态，只是没写进 schema。
- 「尚未支持」也不能当三态里某一格的别名：它不 1:1 对应 F（I161 若去年非 blocking 仍是办成了）、也不 1:1 对应 NF（功能未实现只是 NF 的一种理由）、更不 1:1 对应 NE（职责外 / 输入坏不是「产品认但还没做」）。所以它只能挂在维上解释三态，或写进 NE/NF 的理由，不能当 overall 同义词。

014 文中的三行问句（挡不挡整句 / 在不在产品定位 / 空间有没有）我只当**分层语言**，不当已接受字段名。消费规则已经在协议里：附加维且地图内空间还没有 → 整句仍可 F、该维 non-blocking（若用户确认去年是附加，§4 未决）；该维是核心且地图内空间还没有 → 整句 NF + 长期优化点（§8.3）；地图外 → NE；输入不成对象 → NE（输入坏），不得 F（009）。本轮不发明上线字段。

### Improvement Proposal
- **Target**: 词表与出口分层。不改 `spec/info-volume.md` 正文，不加 schema 字段，不取对外中文名。
- **Change**: 禁止第四个整体状态进入 judge 出口和报表主列（含 review 把 2+3 收成一格）。若做「尚未支持」，只允许作为维级说明，或 NE/NF 理由里的「差在哪儿」，并且必须能回指：挡不挡整句、在不在产品地图、空间有没有。三态展示名走章程 §4.4，不在本 issue 取名。
