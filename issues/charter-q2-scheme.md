# Charter — 第二问的方案：开格子是不是就是新增一个 judge 结果标签

> 本轮只锁一句方案，不改代码，不改协议正文，不改前端。
> 用户 `/council`：开第二问自己的格子，本质上不就是新增一个 judge 结果的标签吗？
> 按 fulfilled 的定位，它是不是只是 not_fulfilled 的补充；该新增一个 judge 结果标签，还是 fulfilled 从 3 态扩到 4 态，还是放到 NE，还是别的方式。给方案。不实现。
> 两问结构已锁（用户标注 / 040 / 046–048），本轮不得再改题面、不得再发明类型表。

## 1. Goal & Definition of Done

- Goal: 钉死第二问的安放方案。用户点名的四个口，加上「别的方式」，必须选出一句能用的方案，不能再只交一份否决清单。
- Done:
  1. 每个根因一个 issue + 现行出口原文 + 已锁 Consensus；
  2. architect 独立重读协议和现行出口后写 Consensus；
  3. 交给用户的是一句方案：这个东西放在哪一层、人看见时是不是一个 judge 结果标签、它不是哪三个口。

「方案」在本轮的工作定义（可证伪）：

1. 能用一句话说清：开第二问自己的格子，在人看见的 judge 结果上，是不是多了一个结果标签；
2. 这一句成立时，必须同时说清：它不是 fulfilled 的第四个词，不是 NE，不是只挂在没办成后面，也不是同一轮 Judge 再写一个 status；
3. 能指出现行出口上，以后若打开，挂在哪一格；现在那一格还不存在，不是因为它属于三个词里的某一个；
4. 不得把「是标签」焊回「所以让 Judge 再填」，也不得把「不让 Judge 再填」焊回「所以不能叫标签，因此没有方案」。
