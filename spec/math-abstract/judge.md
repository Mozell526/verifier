# Judge 判定逻辑的数学抽象（不变式内核 J 与映射管线）

> 状态：抽象层协议。本文只固化判定逻辑的数学骨架——什么是不变的、什么是可替换的，
> 不是实现计划。业务语义以 `spec/alg/fulfilled.md`（轴1）、`spec/alg/capability_carrier.md`
>（轴2）、`spec/alg/authority.md`、`spec/alg/material-positioning.md` 为准；
> 本文与它们冲突时，以各协议第一章为准，回来修本文。

## 1. 不变式内核 J（即轴2 的数学抽象）

整个判定体系收敛到一个内核：

```text
J(未达成期望, 能力空间快照) → 三态 + 自认 + 引用
```

注明：J 就是轴2（能力承载判定，`spec/alg/capability_carrier.md`）的数学抽象——
三出口即轴2 的三态，不存在另一套判定。本文通篇写 J 的地方，读作轴2 即可。

记：

```text
J : F × G → V
  F   未达成期望（一条；不折叠，多条各判各的）
  G   能力空间快照（受治理资料在某一 revision 上的定格）
  V   三态 × 自认 × 引用
      三态 ∈ { 做不了, 做错了, 说不清 }
      自认：判"做不了"必须携带资料层自认证据（缺维度/缺值/缺操作符/is_supported=false
            或形态等价物），live 话术不算；
            对称地，判"做错了"是合取推导——该期望未达成 ∧ G 证明承载得了，
            证据同样只从 G 取，不看交付内容（§7 第 2 条）
      引用：每个结论携带可回溯 citations，且落在 provider 声明的引用空间内；
            "说不清"必带差在哪儿 + 成因（缺料，或期望与能力空间的口径分歧）
```

J 的关键性质只有一条：**J 不关心两个实参是怎么来的。**

J 的定义域就是"一条未达成期望"和"一份能力空间快照"这两个值本身。
期望是人工写的、C 推导的、还是缓存里读的；快照是 YAML 装载的、探针探出来的、
还是调用方声明的——这些差异全部被压进实参的元数据（§6），不进入 J 的判定逻辑。
这就是"揣测不越轴"的数学形态：J 没有旁路输入，想偷看这次交付了什么、
live 说了什么话，在类型上就办不到。

## 2. 轴1 作为映射模式

轴1（办成了没有）在本框架里不是另一个判定内核，而是一组映射的复合：

```text
d(·) → 交付快照        d : X → D    x = live 一次运行的原始现场
e(·) → 期望集          e : Y → E    y = 需求侧输入（用户诉求、业务上下文、reference 线索）
C(d(x), e(y)) → 达成/未达成 + 未达成期望集
                       C : D × E → { 达成 } ∪ ( { 未达成 } × P(E) )
```

复合起来：

```text
f = C ∘ (d, e)    f(x, y) → 未达成期望（集）
```

C 是比较器：拿交付快照对期望集逐条对账，判"达成/未达成"，并把未达成的那部分
期望原样交出。轴1 的输出不是一个分数，而是**一个集合**——正是这个集合作为
J 的第一实参喂给轴2。轴1 判"达成"或"说不清"的 case，未达成期望集为空或未定义，
J 不适用、不跑（结构保证，非纪律要求）。

## 3. 完整管线

```text
J( C(d(x), e(y)), g(z) ) → 三态 + 自认 + 引用

其中  g(·) → 能力空间快照    g : Z → G    z = 项目的受治理资料现场
```

展开为数据流：

```text
x（运行现场） ──d──→ 交付快照 ─┐
                              ├─ C ──→ 达成 → 结束（J 不适用）
y（需求侧）   ──e──→ 期望集  ─┘        └──→ 未达成期望集 F
                                              │（逐条）
z（资料现场） ──g──→ 能力空间快照 G ──────────┤
                                              ↓
                                        J(f_i, G) → 三态 + 自认 + 引用
```

时序约束是管线固有的：g 的快照在判定时定格（同维度同快照幂等）；
J 在 C 完成之后运行（判后派生）；J 的输出永不回流到 C 的任何输入。

## 4. 判定逻辑唯一，项目差异只在 provider

```text
项目唯一的：J 和 C ——判定逻辑本身
项目各异的：d / e / g 的 provider ——三个映射怎么实现、从哪取数
```

这是本框架的分层定理：任何"这个项目判法不一样"的诉求，
都必须先被翻译成"这个项目的 d / e / g（或其物料）不一样"。
翻译不出来的，说明它试图修改 J 或 C 本身——那是协议变更，
走协议评审，不走项目接入。

反过来，接入一个新项目的全部工作量 = 提供三个映射的实现：
交付快照怎么取（d）、期望集怎么来（e）、能力空间快照怎么建（g）。
J 与 C 一行不改。

## 5. 既有机制的归位：都是 provider，不是第二套判定逻辑

现有各机制在本框架下各有唯一位置。它们不是不同的判法，
是同一个 J / C 的不同供料方式：

| 既有机制 | 归位 | 说明 |
|---|---|---|
| 受治理 YAML 物料 + `key_live` 消费 | g 的 provider | 按稳定 key 实时取数，源漂移自动吸收；快照 revision 进审计 |
| source 阅读（调查期读源码/文档） | g 的 provider | 产出的是资料证据，进能力空间；不产出结论 |
| `llm_probe` | g 的 provider | 探针探测得到的能力证据，同样带出处与信任档位入 G |
| caller-stated（调用方声明的能力/边界） | g 的 provider（叠加层） | 只准作为 G 的一个低信任档叠加层或注意力提示；不准进轴1 计分（§7） |
| 调查资料（investigation 产物） | f / g 输出的缓存 | 是映射输出的物化缓存，带 staleness；缓存过期 ≠ 判定逻辑变化，按漂移协议重算/重验 |
| adapter / live / show_schema | d 的 provider | 交付快照怎么从运行现场取出来，是 d 的实现细节 |
| judge_boundary | f / g 的定义域声明 | **不是 provider**。它声明哪些期望进得了 F、哪些资料算得上 G（定义域），不供任何值 |

归位的判别式：一个机制如果**供出一个值**（交付、期望、能力证据），它是 provider；
如果**限定哪些值合法**，它是定义域声明；如果**下三态结论**，它就是在冒充 J——不许。

## 6. 共同纪律：每个映射输出带三件套

d / e / g 的每一个输出，无论 provider 是谁，必须携带：

```text
出处（provenance）      这个值从哪份资料/哪次运行/谁的声明来，可回溯
信任档位（trust tier）  normative_rule / external_fact > inlive_boundary > current_behavior
                        的定位序，或形态等价的分档；caller-stated 天然低档
新鲜度（staleness）     值定格于哪个 revision；源漂移后按消费模式路由重算/重验
```

J 消费这三件套的方式是确定性的：**g 缺失或低置信 → 诚实的"不确定"（说不清 + 差在哪儿 + 缺料），
不是一个自信的错误结论。**没有查证过 ≠ 查不了；低档资料不能解除高档问题的 Gate；
资料不够就说资料不够，把缺料清单留给人，而不是让 J 用常识补齐。

这条纪律是内核不变式的对偶面：J 不关心实参怎么来的（§1），
恰恰因为实参自己把"怎么来的"带在身上，J 只需按档位与新鲜度确定性地降级或拒判。

## 7. 结构性约束（轴1 vs 轴2）

以下是抽象层的硬约束，不是代码规范：

1. **轴2 判后派生，永不改写轴1。** J 在 C 完成后运行；J 的任何输出不回流到
   C 的实参、不改 C 的结论、不进轴1 计分。轴1 判定时轴2 通道物理上不存在。
2. **J 永不查看本次交付。** d(x) 不在 J 的定义域里。"做错了"是合取推导
   （未达成 ∧ 承载得了），不是 J 看了交付内容判出来的。
3. **caller-stated 只进 g / 注意力，不进轴1。** 调用方声明可以作为能力空间的
   低信任叠加层，或作为提示 Judge 注意某处的信号；不得作为 e 的来源、
   不得给 C 的对账结果洗分。
4. **"自认"只认资料。** live 的"暂不支持"话术不能自我背书为承载性证据；
   防循环格挡在信任档位上体现（被测系统自己说"是"的东西是被量的对象，不是尺子）。
5. **单位是期望，不折叠。** F 中每条期望独立过 J；case 级只做罗列展示，
   不定义 case 级单值。
6. **覆盖无漏格。** C 三出口穷尽 → 只有未达成进 J → J 三出口穷尽且
   "说不清"成因穷尽。任何案子都有唯一落点。
7. **provider 失败 ≠ 说不清。** 映射运行失败（装载失败、重试耗尽）是本次运行
   error，不得伪装成 J 的"说不清"业务结论。

## 8. 演化含义（简记）

本文主体是抽象逻辑框架；对实现演化只留两句方向性的话：

- **provider 合同一等公民化**：d / e / g 的接入合同（值 + 三件套 + 引用空间声明）
  应当是显式的、装载期可校验的一等对象，而不是散落的 getattr 约定；
- **把硬依赖剥成 provider**：凡是 J / C 附近直接摸具体物料、具体项目函数的地方，
  都是待剥离的隐式 provider，逐步收敛到 §5 的归位表里。

实施细节（分层拆分、fail-fast、形态族）见 `spec/alg/capability_carrier-generalization.md`
的既有方案，不在本文重复。
